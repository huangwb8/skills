# 优化计划: auto-test-skill 多轮迭代测试工作流

**计划日期**: 2026-01-12
**计划ID**: v202601121109
**目标**: 重构 auto-test-skill 以支持多轮A轮测试 + B轮质量检查的完整迭代工作流

---

## 需求概述

当前 auto-test-skill 的工作流相对简单，需要增强以支持以下能力：

1. **参数化测试轮次**：新增"自动测试轮次"参数，默认为1，用户可指定更多轮次
2. **规范化的测试命名**：使用 `v{年}{月}{日}{时}{分}` 格式（如 `v202612010307`）
3. **A轮测试循环**：每轮包括问题分析 → 计划制定 → 优化执行 → 轻量测试
4. **B轮质量检查**：基于六大质量原则的系统性检查
5. **清晰的目录结构**：plans/ 和 tests/ 分离，每轮测试独立目录

### 阶段 1: 配置文件扩展

**目标**: 添加"测试轮次"参数和相关配置

**修改文件**: [config.yaml](../config.yaml)

**新增配置项**:

```yaml
# 测试轮次配置
test_rounds:
  # A轮测试默认轮次
  default_a_rounds: 1
  # 最大A轮测试轮次（防止无限循环）
  max_a_rounds: 10

# B轮检查配置
b_round_check:
  # 是否启用B轮检查
  enabled: true
  # 检查维度（六大质量原则）
  dimensions:
    - name: "hardcoded_ai_plan"
      label: "硬编码/AI功能规划"
      description: "检查确定性操作是否应硬编码，启发式判断是否由AI处理"
    - name: "redundancy_check"
      label: "冗余残留错误检查"
      description: "检查是否存在重复逻辑、残留引用、僵尸代码"
    - name: "security_check"
      label: "安全性检查"
      description: "检查输入验证、路径处理、敏感信息、权限控制"
    - name: "overdesign_check"
      label: "过度设计检查"
      description: "检查是否存在YAGNI违反、不必要的抽象、配置臃肿"
    - name: "generality_check"
      label: "通用性检查"
      description: "检查是否包含年份、场景限制、平台依赖等非通用性设定"
    - name: "consistency_check"
      label: "一致性检查"
      description: "检查YAML frontmatter、SKILL.md、config.yaml三者是否一致"

# 目录配置
directories:
  # 规划文档目录（相对于skill根目录）
  plans: "plans"
  # 测试目录（相对于skill根目录）
  tests: "tests"
  # 测试会话命名格式
  session_format: "v{year}{month}{day}{hour}{minute}"

```yaml
---
name: auto-test-skill

description: |
  自动化测试驱动优化技能 - 用于AI辅助开发后的系统性测试和迭代优化。

  **核心能力**:

  - 规范化的测试会话命名（vYYYYMMDDHHMM格式）

  - tests/B轮-{测试ID}/: B轮优化验证目录

```

#### 2.2 新增工作流程章节

替换原有的"阶段1-6"结构为：

```markdown
## 工作流程

### 概览

```
用户输入 → [A轮测试 × N] → B轮质量检查 → B轮优化 → 完成
           ↓                    ↓
    每轮A轮:         六大质量原则检查:
    分析→计划→测试   - 硬编码/AI规划
                     - 冗余残留检查
                     - 安全性检查
                     - 过度设计检查
                     - 通用性检查
                     - 一致性检查
```

### A轮测试流程（可重复N次）

#### A.1 测试会话初始化

**目标**: 创建测试会话，生成测试ID

**输入**:
- 目标技能根目录路径
- 当前轮次（第1轮时为初始状态）

**输出**: 测试ID

**操作步骤**:
1. 获取当前时间，格式化为 `v{年}{月}{日}{时}{分}`
   - 年份4位，月日时分各2位
   - 示例: `v202601121109`
2. 检查目标技能目录下是否存在 `plans/` 和 `tests/` 目录
3. 如果不存在，创建这两个目录

**测试ID格式保证**:
- 基于测试开始时间的分钟级时间戳
- 同一分钟内不可能有多个测试开始（串行执行）
- 因此保证测试ID的唯一性

#### A.2 问题分析与计划生成

**目标**: 分析当前状态，生成结构化的问题报告和改进建议

**输入**:
- 目标技能的当前状态（文件、代码、配置等）
- 上一轮测试的报告（如果存在）

**输出**: `plans/{测试ID}.md`

**文档结构**:
```markdown
# 问题分析与改进建议: {技能名称}

**测试ID**: v202601121109
**分析时间**: 2026-01-12 11:09
**上一轮测试**: v202601121000 (如果是首轮则写"无")

## 问题清单

### P0级问题（阻塞性）
- [ ] 问题描述
  - **位置**: 文件:行号
  - **影响**: 具体影响描述
  - **建议**: 修复建议

### P1级问题（严重）
...

### P2级问题（中等）
...
```

**问题来源**:
- 上一轮测试发现的问题
- 静态代码分析发现的问题
- 文档一致性检查发现的问题
- 用户反馈的问题

#### A.3 优化执行与轻量测试

**目标**: 根据计划执行优化，通过轻量测试验证

**输入**: `plans/{测试ID}.md`

**输出**: 优化后的技能代码 + 测试报告

**操作步骤**:
1. 创建测试目录 `tests/{测试ID}/`
2. 在测试目录下创建子结构:
   ```
   tests/{测试ID}/
   ├── TEST_PLAN.md       # 从 plans/{测试ID}.md 复制
   ├── TEST_REPORT.md     # 测试执行后填写
   ├── _artifacts/        # 中间文件和输出
   └── _scripts/          # 测试脚本（如需要）
   ```
3. 按照 TEST_PLAN.md 中的问题优先级顺序执行优化
4. 每完成一个优化，进行轻量测试验证
5. 将所有中间文件保存在 `_artifacts/` 中
6. 完成 TEST_REPORT.md

**轻量测试原则**:
- 仅验证核心功能是否正常运行
- 不追求全面的测试覆盖
- 快速验证，不拖慢迭代速度
- 测试结果记录在 TEST_REPORT.md 中

#### A.4 迭代判断

**目标**: 决定是否继续下一轮A轮测试

**判断条件**:
- 如果用户指定的A轮测试轮次未完成 → 继续下一轮
- 如果P0/P1问题未全部解决 → 建议继续下一轮
- 如果测试报告显示存在阻塞性问题 → 继续下一轮

**下一轮操作**:
- 返回 A.1，生成新的测试ID
- 基于当前最新状态进行分析

### B轮质量检查流程

#### B.1 质量检查执行

**目标**: 基于六大质量原则进行系统性检查

**输入**: A轮测试后的技能最新状态

**输出**: `plans/B轮-{测试ID}.md`

**检查维度**:

1. **硬编码/AI功能规划检查**
   - 确定性操作是否应硬编码到 scripts/？
   - AI动态处理的逻辑是否合理？
   - 可配置参数是否提取到 config.yaml？

2. **冗余残留错误检查**
   - 是否存在重复逻辑？
   - 删除功能后引用是否清理？
   - YAML/SKILL.md/config.yaml 三者是否一致？
   - 是否存在未被引用的僵尸文件？

3. **安全性检查**
   - 输入验证是否充分？
   - 文件路径是否规范化？
   - 是否泄露敏感信息？
   - 权限控制是否合理？

4. **过度设计检查**
   - 是否存在YAGNI违反（未来才用的功能）？
   - 是否有更简单的实现方式？
   - 抽象是否增加了不必要的复杂性？
   - 配置项是否过多？

5. **通用性检查**
   - 是否包含具体年份或日期？
   - 是否过度限定使用场景？
   - 是否不必要地依赖特定平台？
   - 是否假设特定语言或文化背景？

6. **一致性检查**
   - YAML frontmatter 与正文描述是否一致？
   - SKILL.md 与 config.yaml 是否一致？
   - 文档中的示例是否反映最新状态？

**文档结构**:
```markdown
# B轮质量检查报告: {技能名称}

**检查ID**: B轮-v202601121109
**检查时间**: 2026-01-12 11:30
**A轮测试**: v202601121109

## 检查结果

### 1. 硬编码/AI功能规划 ✅/⚠️/❌
**状态**: 通过/发现问题
**发现**:
- (如果有问题) 问题描述
  - **位置**: 文件:行号
  - **建议**: 改进建议

### 2. 冗余残留错误检查 ✅/⚠️/❌
...

(重复上述结构，覆盖所有六个维度)

## 改进建议汇总

### P0级（必须修复）
...

### P1级（强烈建议）
...

### P2级（可选优化）
...
```

#### B.2 B轮优化执行

**目标**: 根据B轮检查结果进行优化

**输入**: `plans/B轮-{测试ID}.md`

**输出**: 优化后的技能代码 + B轮测试报告

**操作步骤**:
1. 创建测试目录 `tests/B轮-{测试ID}/`
2. 在测试目录下创建子结构（同A轮）
3. 按照优先级顺序执行B轮优化
4. 进行轻量测试验证
5. 完成 B轮_TEST_REPORT.md
