# Better Prompt — 用户使用指南

本 README 面向**使用者**：如何触发并正确使用 `better-prompt` skill。
执行指令与硬性规范在 `SKILL.md`；默认参数在 `config.yaml`。

## ✨ 快速开始

### 最推荐用法

```
优化这个 prompt：帮我写个爬虫
```

技能会自动分析你的简陋 prompt，并输出符合最佳实践的高质量版本。

### 场景化变异用法

**指定目标模型**：

```
优化这个 prompt（针对推理模型）：分析用户反馈，找出主要问题
```

| 你的需求 | 推荐参数 | 理由 |
|---------|---------|------|
| 精确执行、代码生成、格式化输出 | `针对 GPT 模型` | 需要详细步骤和明确逻辑 |
| 复杂推理、多步规划、开放性任务 | `针对推理模型` | 给高层目标，保留灵活性 |

**指定场景类型**：

```
优化这个代码生成类 prompt：写一个排序函数
```

支持的场景类型：
- `代码生成类` — 关注语言框架、代码风格、错误处理
- `文本分析类` — 关注输出格式、分析维度、分类标准
- `创意写作类` — 关注风格语调、目标受众、长度约束
- `多轮对话类` — 关注角色定义、状态管理、异常处理

## 📖 设计理念

### 核心价值

你写了一个 prompt，但效果不好？`better-prompt` 帮你把它优化成"专业版"。

基于 **OpenAI** 和 **Anthropic** 官方最佳实践，采用五维度优化框架：

| 维度 | 优化内容 | 优先级 |
|------|---------|--------|
| **清晰度** | 消除歧义，让指令更明确 | P0 |
| **完整性** | 补充缺失的上下文和约束 | P0 |
| **结构化** | 用 Markdown/XML 标签组织内容 | P1 |
| **示例性** | 添加输入输出示例（few-shot） | P2 |
| **约束性** | 明确边界（做什么/不做什么） | P2 |

### 工作原理

```
你输入：简陋的 prompt
    ↓
技能分析：识别核心任务、缺失要素、改进空间
    ↓
技能重组：按 Identity → Instructions → Examples → Context 结构重组
    ↓
你得到：符合最佳实践的高质量 prompt
```

## ❓ 常见问题

### Q：优化后的 prompt 太长了，我需要全部使用吗？

A：不需要。优化后的 prompt 是"完整版"，你可以根据实际需求：
- **精简版**：只保留 Identity + Instructions
- **标准版**：Identity + Instructions + Constraints
- **完整版**：全部使用（适合复杂任务）

### Q：GPT 模型和推理模型的优化有什么区别？

A：

| 模型类型 | 优化策略 | 类比 |
|---------|---------|------|
| GPT 模型 | 提供详细步骤和明确逻辑 | 像指导初级员工，需要明确指令 |
| 推理模型 | 给高层目标，保留灵活性 | 像指导资深同事，只需说目标 |

如果不确定，默认使用 GPT 模型优化策略。

### Q：我的 prompt 已经很好了，还需要优化吗？

A：可以使用技能进行"体检"——看看是否有改进空间。即使小优化，也可能带来显著的效果提升。

### Q：优化后的 prompt 可以用于其他 AI 平台吗？

A：可以。优化框架基于通用的 Prompt 工程最佳实践，适用于 Claude、GPT、Gemini 等主流模型。
