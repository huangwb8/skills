# humanization 防御性写作优化与验证

本轮按 [优化计划](../plans/2026-11-12-humanization-defensive-writing-optimization.md) 实施 P0–P2，架构与兼容决策见 [实施对账](../plans/2026-11-12-humanization-defensive-writing-implementation.md)。交付范围是开发源码、运行契约、回归和评测材料；未发布、未更新系统安装副本，未修改 Kernel。

## 实现结论

新增 Skill 自有 defensive-framing 混合 Pack，与 revision-readiness 分别提供 required 结果。同组三名审查者对两项命题分别投票；控制入口核对冻结稿件、运行身份、真实结果文件哈希、名单和票数。任何已标记的实质异议都须结案，不能被两票 pass 覆盖。修复需要新 attempt，驳回需要原文与候选锚点及理由；脚本不认证身份或裁决语义。

专项规则按删除影响、来源、回应对象、重复功能和替代表达五问识别必要限定与无效防御。科学范围、医学风险、法律权责不因“更直接”而删除，也不规定每项主张最多几个限定。线索扫描只定位，最多保留配置规定数量，并记录总量和截断；无论有无命中，语义判断都需要真实审查。

新增 required 和审查证据合同属于不兼容批准语义，Skill 更新为 3.0.0，原交付 Pack 更新为 2.0.0，新 Pack 为 1.0.0。用户文本参数、working/ready 图及控制回执协议保留。旧事件不改写，旧批准只能由原快照读回，不能升格为双门禁批准。

## 工程验收

使用安装器强制确认的生产 BSK 2.1.6、托管 Python 3.12.14。Kernel 包测试、humanization 保护/运行回归和本地安装入口测试共 **369 项通过**；5 项名称含 remote 的安装器测试不在本次本地接入范围。保留安装器既有 locale 弃用警告。strict Skill 结构检查、公共约束及双语 README 检查通过。

覆盖两项 required 任一缺失或非通过、错轮/错稿/错 schema、缺票/重复文件/硬链接、假锚点、实质异议未结案、保留原文、只诊断、普通英文、LaTeX、冻结后变化、幂等、中断恢复、回执重建和事件重放。合成票据测试只验证协议，不代表真实三人审查。

独立代码审查发现合法大文本可能产生超出 BSK 输出预算的线索列表，已用同一反例复验修复：80000 个命中只保存 128 个位置，明确 truncated，语义状态仍 unchecked。初次回归还发现 BSK 审计脱敏会遮蔽旧审查字段；回读现依据已绑定的 completed/pass 事件，并重验外部 RESULT.md 字节与投票证据，不把脱敏记录当作原始审查 JSON。

临时安装副本从无关工作目录加载成功；两项 Verifier、两种领域 State 和唯一入口均可发现。清理了目标源目录中已有的旧 Python 缓存；本轮工具缓存均归入 .bensz-api。

## 真实宿主与 Gate 链路

同组三名真实宿主子 Agent 审查临时安装副本冻结的合成稿。首稿把“观察相关、未外部验证、不能推断因果或临床获益”改为“证实改善症状并有临床获益”，两项命题均获三票 fail，Kernel Gate 拒绝，状态保持 working。主 Agent 先 retry 到 edit-2，再恢复原有相关性和全部必要边界，只删除假想反驳；三人重新读取新身份和稿件，两项均获三票 pass。入口返回 ready，Gate=allow，事件绑定有效；随后已批准回读返回 already_ready。

另在任务副本临时追加免责声明，入口实际返回 evidence_changed_retry_required；测试随即恢复原冻结字节。事件重放通过。全链路共两轮审查，未耗尽五轮预算；五轮停止规则仍属于主 Agent 契约，本轮没有伪称实测了五轮真实模型循环。

## P2 设计与解释边界

用户本轮没有可提供的真实长文。独立语料 Agent 构造 12 个开发单元和 24 个保留单元，中英文各半，包含 8 条保留长段落、医学/法律/科研必要限定、优秀原文和只诊断。语料构造未读取新实现与计划。三个条件分别为旧编辑规则、旧规则加专项编辑规则、专项规则与审查契约下的候选；每条件两次生成，共 216 份候选，第二次使用全新独立上下文。初次同 Agent 的重复考虑仅作试跑，没有计作正式第二次生成。

生成者只读取输入与输出模式，不读取预期不变量。匿名映射在生成后固定，三名新上下文评审只看到原文和 A/B/C 候选，逐项判断安全与防御性残留，并允许原文获胜或平局。对照对象是生成阶段和离线审查策略，不是 216 次完整生产 BSK 发布；实际受控链路另行验证。

所有 Agent 使用宿主继承设置，未指定模型覆盖。精确模型版本、温度、token 计费与模型服务延迟未由工具披露，不填推测数字。独立上下文不能消除同模型偏差；Agent 评价也不能替代作者/领域评审。

## P2 结果与推广决策

三名评审均完成 72 组比较，覆盖 216 份候选。下表仅统计 24 个保留输入 × 两次独立上下文生成；每条件 48 份候选，每命题共 144 张票。同一输入的重复和同模型评审不能当作独立人群样本，未计算显著性。

| 条件 | 语义通过票 | 防御性通过票 | 双命题均获多数通过 | 无任何未决异议的候选 |
| --- | --- | --- | --- | --- |
| 旧编辑规则 | 142/144 | 89/144 | 31/48 | 27/48 |
| 新增编辑规则 | 144/144 | 144/144 | 48/48 | 48/48 |
| 新规则与专项审查契约 | 144/144 | 144/144 | 48/48 | 48/48 |

“无未决异议”是离线保守策略统计，不是 48 次 BSK 批准。旧规则的两张语义异议分别涉及把 single successful collection 改为 first collection，以及诊断中把无依据的预防性辩解误当成不可删除的独立限定；另外两位并未都判语义失败，分歧原样保留，没有以多数票消除证据。

对于标记为防御性问题的 13 个保留输入，两次生成形成 26 组，三人共给出 78 组最佳候选选择：仅加规则有 75 次被选为最佳且基线未入选，1 次与基线同列最佳，2 次两者均未入选；带专项审查契约的条件有 77 次优于基线的最佳选择、1 次并列。后者对“仅加规则”只有 2 次独占最佳，另外 76 次平局。原文在全部比较中 96 次进入最佳集合，没有被预设为必输对照。

这支持新增编辑规则在本组构造样本上的收益，也表明专项命题能识别“语义安全但防御性表达仍重”的旧稿；但**没有建立新 Verifier 相对仅加规则的独立增量收益**。两组新规则候选都未被审查拒绝，因而没有真实发生由专项意见驱动的修稿收益。加入契约还改变了生成者看到的指令，观察到的微小差异不能单独归因于 Gate。

正式统计使用 6 次独立生成 Agent 调用、3 次匿名审查调用；成功/失败工程链复用了这三名审查者并追加一轮调用。审查启动不因两个命题翻倍。计费 token、每条件模型服务延迟和生产长期平均轮数不可观测，不推算成本；两轮真实短稿链不能代表长篇成本。

**推广决策：** 本轮交付开发源双 required 原型，保留用户计划要求的独立拒绝与异议结案能力，但不发布或安装，也不将其宣传为已验证的默认改进。真实长文、作者/领域评审和可分离的增量收益仍是推广前门槛；如果后续仍只看到规则收益，应按原计划将专项 Pack 降为 advisory 或撤回，不能用工程通过代替该决策。用户暂无真实稿件，所以 P2 已完成可执行的合成对照与人工反馈入口，真实稿件和人工评价仍未验证。
