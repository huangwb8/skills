# `bensz-rmd-rules` 统计推断完整性优化计划

## 问题与证据

用户反馈：AI 常把论文分析停在参数点估计 `a = ?`，没有主动评估能否提供置信区间、p 值等推断证据。当前 Skill **并非完全没有这方面要求**：`SKILL.md:36` 要求收集“统计边界”，`:60` 要求解释不确定性；`references/interpretation_templates.md:44,53` 对部分回归场景明确要求效应量、CI 和 p/q；`references/serial_review_protocol.md:17` 要求审查效应与不确定性。

问题在于这些要求主要落在**解读与事后审查**，没有成为分析开始前对每个关键参数的决策、计算和交付契约：

1. `SKILL.md:49-60` 的实施步骤没有规定“识别关键估计对象 → 判断可用推断方法 → 计算区间/检验 → 报告”的步骤；`templates/analysis_plan_template.yaml:15-21` 只笼统要求统计计算与数值断言。
2. `references/four_tier_interpretation_framework.md:24-28` 只要求至少一类不确定性或稳定性证据，无法保证**每个关键推断结果**有适当区间；`references/interpretation_templates.md:17-20` 的通用示例仍可只填点估计与笼统的不确定性说明。
3. `config.yaml:352-354` 默认将 `require_uncertainty_hits` 设为 `false`；即使开启，`scripts/check_interpretation_quality.py:36-38,723-726` 也只检查 CI/SE/bootstrap/CV 等词语是否出现，不核验对应参数的区间、p 值、计算来源或适用性。图表覆盖检查同样只识别文字要素（`scripts/check_figure_table_interpretation.py:362-373`）。
4. `references/delivery_verification.md:5-18` 和 `references/workflow_checklist.md:20-39` 没有逐参数的推断完整性与“不可估计”记录项。由此，点估计结果可能通过现有交付流程。这是**契约缺口**，不是已经用真实项目复现出的失败率；实施时需用针对性案例验证。

## 目标与边界

对论文级、需要从样本外推的关键估计对象，默认主动规划并在方法允许时报告：**估计值及单位/对比、适当的 95% CI、检验问题明确时的 p 值**；多重检验时同时说明调整方法和 q 值或调整后 p 值。95% 是默认呈现水平，研究方案另有规定时按预先声明的水平执行。结果须有方法、样本量/事件数、模型或重抽样设置、代码与数据来源。

不能把“所有 `a` 都要算 p 值”写成规则。固定总体的描述量、调参常数、不可定义零假设的指标等可以不做显著性检验；样本过少、完全分离、非独立观测、模型假设不成立、没有有效抽样机制等情形不能伪造 CI/p。此时须写明原因、可做的替代分析及结论限制。CI、p 值和统计显著性不能代替效应大小、实际意义与因果识别。

本计划仅优化 `bensz-rmd-rules` 的分析与报告契约，不预设统计检验、R 包或统一结果数据结构，也不引入 State、Verifier、Pack、Gate。现阶段不改 Skill 源码、不运行全量统计分析。

## 实施方案

### P1：把推断决策移到计算之前

1. 在 `SKILL.md` 的“输入”和“执行步骤”加入简短硬要求：列出主要与次要结果的**估计对象清单**，逐项确定目标人群/样本、观察单位、对比或参考点、效应尺度、研究设计、缺失与依赖结构、推断目的（描述/估计/检验/预测）、是否需要 CI/p、可估计性和方法理由。已有预注册或方案优先，不能事后为显著性更换主终点或检验。
2. 新增 `references/statistical_inference_protocol.md` 承载决策细节和简短示例：优先按设计选择有效的解析区间/检验；必要时采用合适的 bootstrap、稳健/聚类方差、置换或精确方法；说明配对、重复测量、删失、权重、缺失、多重比较及模型诊断如何影响估计。不要给所有分析套用同一种 Wald CI 或 t 检验。
3. 在 `templates/analysis_plan_template.yaml` 增加可选的 `inference` 示例节点，记录每个关键参数的估计对象、方法、CI 水平、零假设/检验尾数、多重比较策略、不可估计条件、结果去向。模板只展示字段与示例，不把示例阈值写成领域固定规则；simple 项目也可用等价的短表或方法说明，不强制建立 pipeline 计划文件。

### P1：让计算结果与报告一一对应

4. 在 `SKILL.md` 和新参考文档中规定：推断结果应在分析层计算并保留未按显著性筛掉的完整表；至少包含参数身份、点估计、单位/尺度、有效 N/事件数、方法、CI 下上限与置信水平，以及适用时的 p 值、调整方法和 q 值。Rmd 只消费这些真实结果，不在正文臆算或拼接数字。对于不适用/失败项，保留显式状态与原因。
5. 更新 `references/interpretation_templates.md`、`references/four_tier_interpretation_framework.md`、`templates/Rmd_simple_template.Rmd` 及主要 Rmd 模板：通用示例应示范“估计值 + CI + 有明确假设时 p/q + 实际意义/局限”；无法推断时示范诚实披露。图表说明按**关键结论**给数值证据，无须给每个装饰性数字计算 p 值。
6. 更新 `references/serial_review_protocol.md`、`references/workflow_checklist.md`、`references/delivery_verification.md`：增加逐项核对，确认主要估计对象的推断结果或不可估计理由、CI 与 p 的方法一致性、配对/聚类/删失处理、多重比较、模型假设、结论是否超出证据。交付摘要区分“已计算并验证”“不适用”“受数据/设计限制”“未运行”。

### P2：校验器与文档保持同一口径

7. 先保留现有文本检查器的**启发式**定位；不要简单将 `require_uncertainty_hits` 改成 `true` 作为完成条件，因为词语命中不证明 CI 已计算，也可能误伤纯描述报告。若实施时为结果表确定了稳定 schema，再增加窄范围确定性检查：关键参数是否有对应估计值、区间界限和状态，CI 上下限/置信水平/数值类型是否合法，p/q 是否在 `[0,1]`；方法是否适当仍由人工/AI 科学审查。检查器须区分 `not_applicable`、`not_estimable` 与 `not_run`，不可把缺失一概报错。
8. 同步 `README.md`、`README_EN.md` 与 `CHANGELOG.md`，说明新默认行为和例外；若修改 `config.yaml` 的可配置默认值，只保留真正需要项目覆盖的参数（例如 `confidence_level: 0.95`），避免与 Rmd `params` 或参考文档双重维护。按项目规则更新版本与 BAC 记录。

## 验收与验证

实施后用最小案例评估是否真正改变 AI 的**分析选择**，而非只改善文字：

| 案例 | 预期行为 |
| --- | --- |
| 两组独立样本的主要均值差 | 先识别估计对象和设计，给差值、95% CI、预先定义假设的 p 值、N 与方法；不只给两组均值。 |
| 配对/重复测量或聚类样本 | 使用匹配设计的区间与检验，不把观测值当独立样本。 |
| 批量特征筛选 | 给完整结果、效应及 CI、原始 p 与适用的多重校正结果；区分探索性发现。 |
| 单组比例或预测性能 | 给适当区间；没有明确零假设时不凭空生成 p 值。 |
| 确定性参数、样本太少或模型不可识别 | 标注不适用或不可估计及原因，不造 CI/p，不作显著性结论。 |

静态验证：检查 `SKILL.md` 正文骨架、公共约束块、config/README/模板引用一致性和旧模式兼容性。轻量执行：用合成 fixture 跑至少一个真实 R/Rmd 入口，复核区间/检验与结果表、报告数字的一致性；保留 `full_data_execution=NOT_RUN`，不得把模拟数据结果写成论文结果。对旧项目不自动迁移既有分析。完成后复核 git diff、CHANGELOG 和 BAC 验证结果。

## 剩余风险

- 统计推断能否成立依赖具体研究设计与数据；Skill 只能强制**主动判断与说明**，不能保证所有参数都有合法 CI/p。
- 纯文本检查器无法证明统计方法正确；核心验收必须查看计算代码、结果表及研究问题之间的对应关系。
- 当前工作机的默认 `python3` 为 3.9.6；后续实施与仓库级验证应先切换到符合项目要求的 Python 3.11+ 环境，不以低版本运行结果冒充完整验证。
