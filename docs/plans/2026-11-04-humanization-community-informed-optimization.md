# humanization：基于社区调查的优化计划

## 通俗解释：究竟要改善什么

一段话即使没有“赋能”“重要意义”，仍可能让人觉得是机器写的：每段都从背景重新讲起，最后再表一次态，读完却说不清申请人究竟要解决哪个问题。

例如，原稿写：“两种处理条件下都观察到了 X。处理条件不同，但 X 是否受其影响尚不清楚。本项目拟比较两种条件下 X 的变化，具有重要意义。”在信息不变的前提下，可以整理为：“两种处理条件下都观察到了 X，但处理条件是否影响 X 尚不清楚。本项目拟比较两种条件下 X 的变化。”改善来自把观察、未知和计划接起来。若原文根本没有未知问题或比较计划，润色不能替作者发明它们。

目标是让申请书表达出作者已有的科学思考，并保持作者愿意认可的声音。社区调查支持补充风格依据、基金语境和删改后的论证检查；这些方法是否有效，需要真实文本对照验证。

## 专业判断：保留什么，补什么

完整调查见 [社区调查报告](../events/2026-11-04-humanization-community-survey.md)。本轮读取了 11 个社区项目的 Skill 入口及重点参考，并核对现有实现；没有修改 `skills/alpha/humanization/`，没有把手写示例当作模型实测结果。

当前 Skill 已具备自然写作原则、四层诊断、事实与独立边界保护、八维比较、两轮内部复核和原文免改。继续叠加同类规则，预计增益有限。最明确的缺口是作者样本的使用契约和基金专属参考；最重要的验证缺口是真实长文与人类判断。至于保护要求过密是否导致改写保守，目前属于待测假设。

还需先消除版本混淆：本机 Codex 安装副本为 1.3.0，仓库为 1.5.0，默认强度、复核轮数和参考材料已有差别。评估必须显式绑定所用版本与正文哈希；本轮不更新安装副本。对其他平台或用户使用哪个版本没有证据，不作推断。

## 目标与范围

优化后的 Skill 应能在保持科学内容、引用和格式边界的条件下，更自然地组织已有论证；能利用作者指定的样本而不借用其事实；能识别申请书语境，保留有依据的研究愿景与明确计划，并知道何时只能提示作者补材料。

本计划继续维护同一个通用 `humanization`，保留普通文章、邮件、学术和技术文字的现有入口。实施以本 Skill 的正文、配置、参考、双语指南、变更记录及相关测试为边界。新写标书、科学论证重建、文献检索、模型微调，以及对其他写作 Skill 的修改，应由独立需求决定。本轮不安装、不提交、不发布。

## 改进方向

### 先明确“内容听谁的、表达参考谁”

输入允许附作者认可的相邻正文或风格样本，不强制提供，也不因缺样本中断普通润色。内容和科学立场继续以授权原稿及作者本轮决定为准。表达偏好依次参考：本轮明确要求、已认可的同文档周边正文、指定的作者样本；都没有时采用任务适合的中性表达。不能把待清理的 AI 草稿自动认作作者风格基准。

只提炼有依据的软偏好，例如如何引出问题、解释到什么程度、术语是否稳定重复、如何承接证据。不要按单篇样本建立标点配额，不复制辨识度高的句子骨架，更不移入样本的研究结果。现有风格卡增加“依据与适用范围”，继续按输出模式决定是否展示；优先扩展现有输入说明，不急于增加 CLI 或必填参数。

依据：调查 S1、S2、S4。对使用者而言，作者感应有具体参照，不能只靠“像资深专家”的角色描述。

### 为基金申请补一份按需参考

沿用 `style_profile=auto`；从明确用途或实际正文判断是否为申请书，再加载基金参考。`nsfc_academic` 保留兼容入口，显式选择该值可使用基金语域，但不据此推断资助机构、项目类别或现行格式。模板要求仅使用作者提供或明确指定的版本。

参考围绕原文已有关系给出判断，而非要求每段填满固定槽位：

| 场景 | 优先改善的关系 | 需要守住的边界 |
| --- | --- | --- |
| 立项依据 | 已知现象怎样引出具体未知，为什么值得研究 | 不凭空补缺口，不宣布未经核实的“首次” |
| 研究内容 | 要回答的问题与研究动作是否能相互对应 | 不把方法名自动改造成新科学问题，不增实验 |
| 研究基础与条件 | 已有结果、资源怎样支持当前计划 | 区分已具备、待落实、计划获得 |
| 风险应对 | 真实风险与原稿已有替代路径是否表达清楚 | 不编造备选方案，不改变停止条件 |
| 创新与预期价值 | 具体差异、拟获得的认识和研究愿景 | 不按论文结果口吻消除合理抱负，不把预期写成成果 |

每个关键判断配“应改、应保留、材料不足”三类短例。采用中文基金语境，不复制 NIH/NSF 的 Aims 数量、页码或栏目。已有 `section_roles` 保持唯一的职责提示，参考文件承接例子与操作判断，不另写一份冲突的章节规范。

依据：S2、S3，结合本地已有章节职责。使用者不必手选复杂参数，常规去机器味也不会自动扩大成研究方案设计。

### 把删除安全落实到论证功能

在现有诊断中增加一个问题：**删掉这句话后，它原本承担的必要作用在哪里保留？** 作用可以是定义、问题陈述、范围限定、比较、证据连接或图表引入。没有其他文字承接时，优先改写其形式，不能仅因像套话就删除。

改后重读受影响段落，检查“这些结果、上述问题、因此”等是否仍有清楚指向；核对引用是否仍支持同一主张。发现唯一图表入口、首次定义或跨节依赖时，再读取其消费位置，不默认扫描整篇。纯重复、无独立含义的包装可以删除，短句、总结、连接词和真实排比按其功能判断。

依据：S1 的功能保护，结合 S4/S6 的必要限定判断。它应成为现有步骤中的小增量，不新增强制审计表或固定段落顺序。

### 区分语言问题与需要作者决定的科学问题

表达能修的直接修；需要新数据、新机制、新方法、改变结论强度或重新确定研究目标的，保留原意，在正文外提出具体缺口。不能为了让论证更顺而把未知写成已知，也不能因编辑者尚未核实文献就把作者结论一律降格。

原则性地保留“原稿—改稿—含义核对”，把“证明零损失”落实为可检查的命题、条件和关系，而非逐字冻结可编辑正文。短文只保留真正相关的内部核对；复杂专业边界再使用现有详细表。默认 `text_only` 与两轮复核预算不变，先验证精简重复说明是否有益，再决定配置调整。

默认行段和 LaTeX 保护继续保留。格式授权不足时给重组建议。当前检查器对英文和命令参数的保守处理已有说明，不把检查器扩展作为自然度改善的前置工程；若后续实测显示必须支持某类明确可编辑区域，另作小范围设计与测试。

依据：S1/S2 的编辑深度与作者控制、系统 `skill-creator` 的最小指导原则。这能减少把普通润色变成审批流程，也避免用“重写”掩盖科学内容改变。

### 用真实写作决定规则取舍

沿用现有八维评价，不另建“人味分”或检测率指标。先做小规模试验，再决定是否投入更完整的盲评。原稿、普通润色、当前 Skill、候选 Skill 同时比较，才能区分基础模型能力、现有规则收益与本次增量。

真实材料优先取作者授权并去敏的申请书，覆盖不同学科和章节；包括可读但机械、论证缺材料、术语密集、优秀原文四类。风格样本与待评文本分开，开发用例和保留评估用例也分开；正式参考示例不能兼任证明效果的测试集。没有授权真实材料时，可以用合成材料检查流程和安全，但质量结论保持待验证。

## 实施范围与顺序

| 阶段 | 工作与产出 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1. 固定基线与最小评估包 | 核对实际加载路径、版本和正文哈希，固定仓库 1.5.0 基线；选 6 个开发单元，含多段上下文；记录用途、权限和关键含义 | 输入可合法使用，版本与保护边界明确；旧安装副本不能混充当前基线，无真实材料时标为合成试验 |
| 2. 实现最小规则增量 | 更新入口、既有自然写作参考和模式库；新增作者声音与基金参考；补来源取舍、正反例和双语指南 | 保留现有参数/输出/通用触发；没有重复规则叠加或新模板强制化 |
| 3. 小规模比较与精简 | 6 单元 × 2 次生成 × 3 个生成条件，共 36 份输出；原稿另作比较对象。先用可用的同一模型/设置评估 | 无已知严重语义/格式回归；能指出具体改善，或明确哪些新增规则应撤回 |
| 4. 保留用例确认与交付 | 首批 12 个未用于开发的单元，覆盖至少 3 类学科语境和 4 类章节；2 次生成、同样 3 条件，共 72 份输出；修订结论与变更记录 | 达到下述安全及质量标准；未完成人类评审则只标记试验版效果 |

这里的单元以完整论证片段为单位，建议同时包含短段与约 800–1500 字的连续中文，避免继续只测数句短文。没有跨模型资源时可以先完成单模型结果，但不得声称已解决 GPT 与其他模型的写作差距。跨模型验证只用于回答具体的可迁移性问题，不是每次更新的默认成本。

拟涉及的核心文件为现有 `SKILL.md`、`config.yaml`、`references/natural-writing.md`、`references/machine-patterns.md`、`references/regression-cases.md`，以及新增的 `references/author-voice.md`、`references/grant-proposals.md`、简短来源记录。入口保留固定正文骨架和公共约束块；仅在默认值或参数真正改变时更新对应配置。版本仍只在配置维护，双语指南与 Skill CHANGELOG 随实现同步。

可重复的自动检查沿用根级公开入口测试位置；评测输入、生成稿、评分、匿名映射和日志留在任务工作区/仓库临时目录，不加入 Skill 的测试夹具目录。根级 CHANGELOG 与 BAC 记录实际交付范围，不提前写入尚未验证的效果声明。

## 如何确认完成

### 语义与使用边界

所有拟交付稿都须保留数字、引用、条件、否定、归因、研究状态及主张强度；样本中的事实没有污染目标稿。语义失败不能被风格平均分抵消。严重回归出现即停止发布该候选，修复受影响规则并重跑相关用例。

继续验证优秀原文免改、真实排比、独立多重限定、普通英文润色、LaTeX/数学/注释保护、纯文本重分段权限、旧参数与普通邮件/技术语域。检查器只覆盖其声明的字面范围；不适用处明确标记人工复核。只有改动安装发现或别名，才运行安装器回归；无需安装到系统目录证明文风有效。

### 写作收益

匿名随机呈现稿件，评审不看生成条件、参考答案和本计划的预期结论。至少两名熟悉相应科研语境的人员独立判断；分歧保留，必要时另行裁决。先判断语义和专业性，再按已有八维比较，必须指向具体句段。允许平局、原稿更好和无法判断。

首批 12 个保留单元中，每个单元先合并其两次生成的比较结果，避免把重复输出当作独立样本；方向相反时记为不稳定，评审分歧未解决时记为无法判断，均不计为胜。预先采用一个工程性推进标准：候选相对当前版本的单元胜数减负数至少为 4，且没有未解决的严重安全回归；同时报告其与普通润色和原稿的比较。这个门槛只用于决定本轮是否值得采用，不表示统计显著或已证明普遍更好。若 12 个单元不足以形成可靠判断，报告不确定性，扩大真实样本前不作泛化宣传。

保留用例揭盲后，若据此改规则，该批数据即成为开发材料。再次声称独立确认时须另用未见用例；仅重复旧用例应标为回归检查。记录所有生成稿的失败与回退，不只统计最后挑出的好稿。

对可拆分的收益做最小消融：作者样本规则有样本/无样本、基金参考启用/不启用，以及重复审查说明精简前后。只回答当前仍不清楚的机制问题，不默认做全部参数组合。未被支持的新增规则撤回；新旧差不多时，保留较简单的版本。

### 工程交付

运行相关保护器测试、Skill 结构/公共约束一致性、引用与文档检查及 `git diff --check`；保存实际命令和结果。核对新增缓存没有写入源码目录，BAC 链可验证。自然度改善依据来自盲评，结构检查通过不能替代它。

## 风险与待确认事项

最大的风险是“规则更完整”却没有更好的文字。用真实样本和原稿对照控制这一点；本轮资料不足以承诺效果。作者样本也可能过短或与申请文体不同，只作软参考。材料缺口则应成为具体作者问题，不能成为反复追问的理由。

真实申请书和作者认可样本尚未提供，这是后续质量确认的依赖，不影响先完成规则草案与合成安全试验。正式试验前需确认材料授权和评审人员；不把真实本子存入公开仓库。本计划不要求采用 State、Verifier、Pack、Kernel 或多代理编排，普通编辑规则与盲评已足以检验当前假设。

本次交付到调查与计划为止。后续实施应按以上优先级逐步验证，保留有证据的改进。
