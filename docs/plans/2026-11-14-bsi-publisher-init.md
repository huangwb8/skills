# BSI 发布者初始化实施计划

## 通俗解释：究竟发生了什么

每位开发者都要有自己的签名钥匙，但不必各自设计存放位置。相当于统一钥匙柜的位置和抽屉标签，里面的钥匙由每个人独立生成。目前需要复制一段 Python 脚本；完成后运行 `bsi init` 即可生成，重复运行核对原来的钥匙，不更换身份。

## 专业判断：问题在哪里

现有包提供授权、签名和验证，却没有发布者初始化入口。手动生成容易出现路径分歧、误覆盖、配置与密钥不一致。用户已确认统一采用 `~/.bensz-skills/config/remote.env` 和 `bsi-keys/{root,release}.pem`。

## 要达到什么目标

提供 `bsi init` 与可复用的 Python API；默认布局一致，支持 `--config-dir` 显式覆盖。初始化只建立发布者材料，不创建 Skill 身份声明、授权、信任策略或安装。现有显式 PEM 参数保持兼容。此次不发布 Python 包、不修改用户真实凭据或已安装环境。

## 改进方向

### 标准布局与独立密钥

根密钥和发布密钥各自随机生成，公钥指纹派生发布者 ID。remote.env 只存三项公开值和两条 PEM 路径，保留其它字节内容，不执行或展开任何 Shell 表达式。POSIX 下新建配置/密钥目录权限 700，密钥、配置及锁文件 600；不回显私钥、环境文件内容或本地路径。

### 核验复用与失败恢复

首次创建采用独占写入；重复调用核对两把 PEM、三项公开值和两条路径，不生成新身份。两把密钥完整而配置尚未追加时，可重新生成公开配置；密钥缺失、损坏、配置部分存在或冲突时明确拒绝。密钥创建中断可能留下不完整目录，保留已有材料并报错，禁止自动覆盖或轮换。进程锁串行化初始化，配置原子替换，并检查写入前是否被其他编辑者修改；不承诺抵御本机高权限攻击或断电事务原子性。

## 实施范围与顺序

1. 新增发布者初始化模块、公开 API 与 CLI，固定输出和失败原因。
2. 增加生成、独立身份、复用、配置恢复、损坏/冲突拒绝、权限、路径链接、并发和脱敏测试。
3. 同步双语 README、协议、变更记录和 BAC，执行包内测试及必要的隔离安装验证。

## 如何确认完成

默认路径可在隔离 HOME 下运行；不同目录生成不同身份；重复调用无内容改变。既有配置保持，拒绝不匹配、部分密钥、链接和不安全权限。生成材料可被原有授权/签名/验证流程消费。CLI 只输出公开字段及稳定状态，运行时失败不泄露私钥或其它配置。测试密钥用后清理，源码和任务日志没有凭据与缓存残留。

## 风险与待确认事项

默认 PEM 为无密码的本地文件，由文件权限保护，开发者自行负责保管和备份；其它密钥方案继续使用现有显式接口。权限与并发的实测验收以当前 macOS 为准。包版本保持现状，新增内容记录 Unreleased，远程发布另行授权。
