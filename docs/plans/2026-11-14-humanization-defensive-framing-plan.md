## 通俗解释：究竟发生了什么

**一句话说明：** AI 润色有时把清楚的判断写成一长串自我辩解；现有 humanization 能查出不少类似套话，却还需要更稳定地判断一段话是否真正回答了问题、有没有把核心意思埋起来。

**具体场景：** 作者写“我们观察到不同队列之间稳定的分子关联”，AI 却改成“需要指出，这不代表已经解决所有肿瘤分类问题，也不能据此证明所有患者受益”。这两条防御性的回应并非由作者提出的主张自然引出，反而让读者找不到原来的重点。相反，如果作者原本写明“关联只在内部队列验证”，这是真正重要的边界，不能为了语气果断而删掉。

**生活类比：** 想象有人回答“今天的会议决定了什么”。一位校对员负责确认回答没有弄错会议决定；另一位校对员负责检查回答是否绕着“我们并没有决定世界上所有问题”打转。前者对应 `revision-readiness`（语义保真），后者对应 `defensive-framing`（无效防御审查）。校对员都不应该替会议编造新决定。

**改变前后：** 现在的审查已能发现重复免责与虚构反方，但对“全段回避判断”“核心贡献被限制淹没”的诊断还不够明确。升级后，审查者不仅指出有问题的词句，还应说明作者实际主张在哪里、哪些限定必须保留，以及怎样修订才算真正解决问题。

## 专业判断：问题在哪里

### 已确认的基础

- 当前 humanization 仅用于**已有文本润色**；不能凭空补充事实、研究结论或作者立场，也不负责从零写作与全局对话风格。
- v3.0.0 已采用主 Agent 编辑、三名独立子 Agent 并行审查、两项 required Verifier（`revision-readiness`、`defensive-framing`）及 BSK Gate；两个命题各须三份有效审查、至少两票 pass、实质异议已结案。
- `references/defensive-writing.md` 已有五问、六类功能分类及 `keep/compress/rewrite/delete/human_review` 处置路径；`regression-cases.md` 已有伪对立、边界压过判断、必要限定保护等案例。
- 这些是**已有设计与契约**，不是本次新发现或已实证的写作收益。源码本身也明确：机械校验、投票与合成用例不能证明自然度提高。

### 尚需解决的缺口

1. **论证级防御识别不充分。** 文字可能没有明显的免责高频词，却用整段内容反驳不存在的极端立场，或用含糊比较回避原文已有判断。
2. **改写目标不够可操作。** 指出“防御性很强”后，主 Agent 容易只删词、换词，未必恢复原稿的核心主张。
3. **长篇累积失衡。** 单段限定看似有用，全文却可能反复解释“没有声称什么”，遮蔽真正贡献；跨章节独立阅读又确实可能需要重复限定，不能机械去重。
4. **审查激励可能反向。** 审查者出于保险心理要求额外免责，导致“反防御”的 Gate 反而诱导更多防御性写作。这是待验证的风险，不应表述为已发生的实测缺陷。
5. **增量效果未被证明。** 需要确认升级 Verifier 比只改主 Agent 写作规则带来更多收益，且不会显著增加误删、反复审查和使用成本。

**影响范围：** 首先影响学术论文、基金申请、技术说明、报告和邮件等已有文本的修订。医学、法律等语域尤其要求保留真正改变决策或责任的限定，不能以“自然”为由删减。

## 要达到什么目标

**用户能看到的变化：** 润色稿更直接地表达原文支持的主张，减少虚假反驳、无效免责和机械对立；真实的证据强度、适用条件、医学风险、法律责任、数字与受保护标记仍完整保留。好的原文允许原样通过。

**系统能验证的变化：** `defensive-framing` 的实质性审查意见能够定位问题、解释实际损害、指明必须保留的信息功能，并给出复查标准；`revision-readiness` 继续独立保证语义与格式安全。两者都通过后才按原有流程放行。

**不在本次范围：** 新建 BSK State、增加第三个 required Verifier、增加审查人数、重构 `parallel-vibe`、让 humanization 接管全部聊天生成、用关键词黑名单或固定否定词比例裁决质量、自动引入作者没有提出的主张。

## 改进方向

### 让 defensive-framing 判断“为什么在辩解”，不只判断“用了什么词”

在现有五问与六类功能分类之上增加**非互斥的审查维度**，不是另造一套分类表：

| 审查维度 | 要识别的问题 | 如何判断修复成功 | 对用户的意义 |
| --- | --- | --- | --- |
| **Defensive Intent**（防御意图） | 回应没人提出的极端观点或虚构反方 | 无信息的反驳消失，真实边界仍保留 | 少看到“我并没有声称能解决一切” |
| **Claim Visibility**（主张可见性） | 原文已有的主要判断被限定、元评论盖住 | 读者能找到原文支持的主张及依据 | 不必从免责声明里猜作者想说什么 |
| **False Dichotomy**（伪对立） | “不是 A，而是 B”把互补、主次或重复写成对立 | 先判关系再选择保留、改写或合并 | 少一些虚假的深刻感 |
| **Judgment Avoidance**（判断回避） | 候选稿弱化或绕开原稿明确作出的比较/判断 | 恢复原稿确定性等级与实际选择 | 不把有结论的稿子改成“各有利弊” |
| **Discourse Balance**（篇章平衡） | 多段、跨节反复免责，使主张与证据失去中心 | 同一阅读单元无无效重复；独立章节的必要限定保留 | 长文更聚焦贡献而非自我辩护 |

所有维度均为**语义判断**。不能仅因出现“需要指出”“不是……而是……”“可能”“不保证”就判 fail。出现真实互斥、临床警示、法律责任或证据边界时应保留。

### 将“正向主张重建”变为明确的编辑与复查策略

主 Agent 先对照原文识别“主张—现有依据—必要边界”三者的关系，再决定保留、压缩、重写还是人工确认。候选稿应优先清楚呈现**原文本来就有**的判断，而不是先替自己辩解。

示例：原稿说“该关联只在内部队列得到验证，我们并未声称解决了所有癌症的分型问题”，且上下文从未讨论“解决所有癌症”。可保留“关联只在内部队列验证”，删除后半句无关反驳；**不能**把它改成“已证明跨癌种普适”或“必然改善临床获益”。

如果缺乏足够上下文来重建正向主句，只做有依据的最小润色或保留原文。审查不强制结论始终在第一句，也不要求每段套用固定的“主张—证据—边界”模板。

**对用户意味着：** 去掉的不是谨慎本身，而是没有发挥作用的辩解；保留下来的依然是可信、准确的内容。

### 让审查意见有证据、有损害说明、有复查终点

扩展现有 `defensive-framing` 审查指引：每个**阻塞性问题**必须有原文/候选位置、问题类型、为什么造成阅读或论证损害、哪些信息必须保留、最小修订方向以及怎样判断它已解决。缺少这些依据的一般风格偏好只能提出建议，不能无限否决。

审查者应先独立概括作者真实主张，再判断无效辩解是否存在，不能直接照搬主 Agent 的诊断。三人仍分别评估两个命题，沿用现有投票、异议结案、冻结文本哈希、attempt 绑定和五轮上限。

**对用户意味着：** Codex 不会为了满足一句“再自然一点”无休止改写；每次返修都指向可理解、可复核的具体问题。

### 防止 Verifier 自己制造更多防御性写作

补充反向约束：不得以“更安全”为由要求添加没有原文依据的免责、风险或外推限制；不得把所有不确定表达当作过度防御；不得通过机械删减让科学判断被错误升级。必要限定的缺失由 `revision-readiness` 阻塞，防御性残留由 `defensive-framing` 判定，二者不以总分互相抵消。

区分**实质性问题**与**纯风格偏好**：前者须引用锚点并修复或结案；后者可保留少数意见，不必为了审查一致而反复重写。任何未知或无法确定的独立边界都不得被“提高自然度”的目标覆盖。

**对用户意味着：** 审查更聪明，而不是变得更苛刻或更繁琐。

### 用消融实验证明新增审查确实值得付出成本

复用现有 `regression-cases.md`，补充**成对的正反案例**：同样含“不能证明”，一个是必要科学边界，一个是无关辩解；同样用“不是……而是……”，一个是真实对立，一个是伪对立；有的段落确实需要谨慎，有的段落只是在逃避明确结论。

评测三个条件：① 当前 v3.0.0；② 仅增强编辑规则；③ 增强规则 + 升级的 `defensive-framing`。允许原文胜出或平局，优先真实长文与人工匿名偏好评价，同时检查语义安全、阻塞误报、审查轮数、模型调用和延迟。若③没有显示相对于②的实际收益，应减小额外审查负担，而不是默认继续叠加规则。

**对用户意味着：** 决定是否保留复杂 Verifier，依据的是实际文本变好了没有，而不是系统看上去有多严密。

## 实施范围与顺序

1. **先固定基线与评价样本。** Codex 核对仓库版本、当前审查契约和既有回归案例；保存旧版对照行为，区分已验证事实与待检验假设。
2. **再完善诊断与编辑规则。** 优先升级 `references/defensive-writing.md`、必要的 `natural-writing.md` 指引与 `SKILL.md`，明确五个新维度和正向主张重建策略；不要先改 Kernel。
3. **随后增强现有 Verifier。** 在 `defensive-framing/VERIFIER.md` 中落实证据化判定、实质问题门槛与反向激励约束；仅当既有审查协议无法承载新增证据时才调整 schema、控制入口及版本，保持旧记录可解释。
4. **最后做回归、消融和文档同步。** 先验证原有 Gate、格式保护与恢复行为没有回归，再比较真实写作效果；只有评测支持才把增强后的规则作为默认生产行为。同步必要的配置版本、README 中英文与 CHANGELOG。

**预期最小改动面：** 以 humanization 的规则文档、现有专项 Verifier 契约及回归样例为主。`control.py`、BSK Pack schema、`config.yaml` 等只有接口或版本确实需要变更时才涉及；不重造状态机或审查编排器。上述路径是计划实施时的候选范围，不能据此认定每个文件都必须修改。

## 如何确认完成

### 写作效果

- 对有真实防御性问题的文本，评审能指出**哪项无效防御被消除**，以及核心主张是否更容易识别；不只比较字数和禁词出现次数。
- 对“可能”“尚不能外推”“仅限成人”“责任限于直接损失”等必要限定，修订不改变证据强度、临床决策或法律责任。
- 对伪对立、判断回避、跨段重复、优秀原文免改、英文和 LaTeX 混合文本，有清楚的通过/失败反例；没有上下文的情况允许保留和人工确认。
- 匿名对比当前版本、仅改规则、规则加 Verifier 的结果，报告样本量、平局、原文胜出、语义错误、误报和调用成本；不以合成测试宣称已证明真实自然度增益。

### 工程安全

- 两个 required Verifier 均按既有协议完成，缺失、失败、`uncertain`、旧 attempt 或证据不匹配不能得到 `ready`。
- 三名审查者的两项判断及实质异议结案逻辑不变；不能用多数票覆盖未结案的语义红线，也不能让普通风格分歧获得无限否决权。
- 保留 `diagnosis_only`、`keep_original`、最大五轮复审、未通过草案交付、原文 token/LaTeX/数字保护以及中断恢复行为。
- 旧版本审查资产不被悄悄升级为新协议的已批准证据；如变更审查字段，验证契约版本和历史回放兼容性。

**验收决策：** 优先保证语义与必要边界没有已确认的严重回归；在此基础上，要求人工评审能够观察到新版的防御性表达改善。若新增 Verifier 的收益不超过单纯改写作规则带来的收益，则不以增加复杂度为目标，保留更小的改动面。

## 风险与待确认事项

| 风险或待确认项 | 处理原则 |
| --- | --- |
| “更直接”被误读为“更肯定” | 保护原文确定性等级，保留所有独立限定；未确定则不强改 |
| 需要的科学/医学/法律提示被当作套话删除 | 加入同词异功能对照与语域保留反例，语义安全优先 |
| 审查标准过严导致不断返修 | 只阻塞可定位、有实质损害的缺陷；风格分歧不无限否决 |
| 三名子 Agent 的一致意见并不独立 | 继续冻结与证据审计，但真实收益用外部匿名评审验证 |
| 扩展 schema 破坏旧运行回放 | 优先复用既有字段；必要变更显式升级契约并做历史兼容验证 |
| 额外审查成本高于改进收益 | 以“规则-only vs 规则+Verifier”消融决定是否继续保留增强逻辑 |
| 评测样本短小、偏向某种文体 | 追加真实长文及中文/英文、学术/技术/职场与高风险语域案例 |
