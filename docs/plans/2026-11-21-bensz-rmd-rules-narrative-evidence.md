# bensz-rmd-rules 科研报告论证优化实施计划

## 读者需要从报告里得到什么

`test-03` 想知道，一份不完整的肿瘤表达谱，能否靠八个坐标保住患者之间的远近关系，以及少测一批基因后，这八个坐标还能不能当作同一把尺子使用。三个问题决定实际取舍。只想找相似患者时，谁答得更准？必须压缩时，八个训练出来的坐标有什么价值？要按坐标本身解释患者时，少测基因会带来多大偏移？这三项已有结果，但读者要在摘要、讨论、另一篇报告和验收宽表之间来回查，才能把它们合成一个判断。

## 问题定位

本轮对照三份既有 HTML、Rmd、研究方案、正式 CSV 和相关实现。报告已做到四段摘要、可追溯的内联数字、可复现入口，并用三人比较和轴符号翻转的假例建立了局部直觉。下列问题出现在需要用这些材料作判断的地方。

| 发现 | 案例与影响 |
| --- | --- |
| 选型规则和实际判定分离 | 主报告第 102 行列阈值，第 198–205 行输出 `decision` 宽表。两类确认场景均满足覆盖门槛，但均未过关系保真与单队列退化门槛，且全词表冻结包又未过坐标漂移门槛。跨癌种还未排除宽词表的实用退化。这些分开的理由值得在正文汇总。核对 `products/decision.csv` 与 `R/output.R:26–63`。 |
| 研究对象在更换指标时变得含混 | 主报告第 78–94、181–192 行依次涉及留出基因答题、近邻重合、冻结坐标漂移。稳定性报告第 100–104 行解释了分半几何与固定模型坐标的区别，但摘要和主报告未把三类判断并列。主摘要说留出基因“独立”出题，第 216 行才限定其来自同一次 RNA 测量。应在首次界定指标时分清患者留出、基因留出和独立测量或临床终点。 |

当前 beta 源码在 [报告规范](../../skills/beta/bensz-rmd-rules/references/report.md#组织成可以读完的证据链) 中已经要求按问题组织证据、用直觉和公式解释方法，并在 [交付规范](../../skills/beta/bensz-rmd-rules/references/delivery.md#先核对结果再读-html) 中要求读成品。可定位的缺口在执行方式。Skill 没明确要求从研究方案中挑出会改变结论的预设判断，给每项安排可读的正文证据，在渲染后实际复述和回查，再修订含混或遗漏之处。代码规范又把正式计算摘录与绘图、制表均写成默认展开，验收重在可见性、前文说明和结果复用，缺少针对可见片段的判据，判断它是否让人理解某个关键数字。多报告规则主要解决编号、顺序和索引。随附的[配对算例](../../skills/beta/bensz-rmd-rules/templates/project/01.01.01-paired-change.Rmd) 演示了单一估计，较少涉及结果冲突、未过阈值和跨报告衔接。成品验收记录覆盖了数字复算、重建和浏览器交互，未给出逐项科学决策的正文验收证据。单次产出足以定位这些契约缺口，具体生成时读取了哪个 Skill 版本、哪些参考段落，以及这一表现的发生率，仍需对照运行确认。

## 优化目标

读者从成品正文就能说明研究在选什么、比较为何能回答所问问题、实际结果改变了什么判断、还缺哪类证据。专业读者可以沿主要结果回查估计式、分母、数据条件和正式产物。详细模型登记、完整结果和诊断仍可从正文中的对应证据入口查到。

实施集中在 beta Skill 的写作指令、报告与交付参考，以及少量运行对照。历史报告及其结果用于构造复现案例，实验实现和项目数据无需参与源码修改。

## 改进方向

### 1. 把研究计划中的判断落实到报告

在 [SKILL.md](../../skills/beta/bensz-rmd-rules/SKILL.md) 现有“界定科学问题”和“完成论文式论证”步骤，给“判断 → 比较与分析单位 → 证据 → 结论边界”增加具体用法。开写前列出最少几项会改变主要选择的判断，并标注它是开发、留出确认、部署检验还是探索诊断。给每项找实际结果及位置。曾预设而没有运行、不可估计、发生方案改变或未达门槛的项，要说明状态及其对结论的影响。计划与正文逐项对应只用于写作和审阅，正文可以自然组织。

多报告沿用已有的阅读入口。主报告给出一项决策的主要证据和适用条件，并把开发消融、稳定性分析等链接到对应小节。选读报告说明自己补上主问题的哪一环。对 `test-03`，开发广筛回答为何留下 PCA 做确认，整队列比较回答该不该采用八维压缩，分半重训和遮挡检验回答关系能否复现以及坐标能否按同一尺度使用。把效应和门槛紧接着写，避免读者自行解释 `TRUE`、`FALSE` 与 `NA`。

### 2. 让通俗解释、公式和结果指向同一个比较

在 [references/report.md](../../skills/beta/bensz-rmd-rules/references/report.md) 的既有段落扩充一个复杂案例，覆盖以下动作。先说这个比较解决什么疑问、同时改变了哪些因素、哪些条件保持可比。关键方法先用一句能复述的白话或明确标注的手算例子，再给与实现相符的公式、符号、方向、分母与不确定性来源。正文紧跟正式结果、比较单位、量级和限制。对成熟且不影响推断的术语缩短解释。长推导、模型目录和明细保留可访问入口。文件名、变量名和双语表头可并存，但读者首先看到清楚的指标名和单位。

例如，冻结坐标漂移小节先让读者想象同一位患者用全部实测基因得到一个位置，再遮去一组基因重算。对两次均能出分的同一确认队列患者，设 $h_i$ 为高覆盖坐标，$z_i$ 为遮挡后坐标，$\bar h$ 为这些患者的高覆盖坐标均值。设配对人数为 $n$，报告量是

$$
\frac{\operatorname{median}_{i}\lVert z_i-h_i\rVert_2}
     {\sqrt{n^{-1}\sum_{i=1}^{n}\lVert h_i-\bar h\rVert_2^2}}.
$$

分子是患者各自移动距离的中位数，分母是原来各患者到队列中心的距离的均方根。四队列实际比值为 0.53–1.11，均超过事先约定的 0.25。与此同时，前十近邻重合率仍为 83.5%–95.3%，四队列的样本出分率为 100%。它们分别回答绝对位置变化、局部相对关系和模型能否返回坐标。证据限于所测冻结包、确认队列以及这次遮挡。稳定性报告中的因子逐轴误差按源训练标准差归一，应采用各自名称并解释两者的单位差异。核对 `R/confirm.R:109–119` 与 `products/confirmation.csv`。

### 3. 用可见代码解释结果怎样算出来

修改 `SKILL.md` 的“把方法、实现和解读连起来”和 `references/report.md` 的代码展示规则。先决定希望读者通过代码理解什么，再从正式实现挑出能回答这个问题的片段。对支撑主要结论的图表，紧邻图表或在明确链接的方法小节展示最影响解读的步骤，例如谁进入配对、怎样处理平局、每项差值的分子分母、各队列怎样加权，或图中的一行怎样由正式结果选出。片段前说明输入对象的单位和角色，片段后指明输出对应表格哪一列、图中哪个点或哪段区间。多个图表共用同一计算时，可解释一次并指向该处。

图层、定制排序或筛选确实改变读图含义时，展示对应代码并说明其作用。读图对象、打印表格、选列和排版可以在渲染时照常执行，根据解释价值决定是否向读者显示。若底层在 `targets` 中计算，从本次正式实现引用聚焦的源代码，必要时用 `eval = FALSE` 展示，保留源码和命名结果的对应关系。碰到长实现，可将核心流程用少量注释讲明，并以公开的合成例子补足直觉。报告渲染继续复用正式估计，避免维护平行算法。只有外部固定汇总可用时，解释实际可见的取数、筛选和图表映射，并如实交代上游计算的可追溯程度。

例如在冻结包验收表旁，优先展示 `R/confirm.R:109–119` 中的计算。用 `keep` 说明为什么同一患者的两份坐标都有效才进入比较，再把 `median(sqrt(rowSums((za-h)^2)))` 与高覆盖半径的计算逐项对应到上一节公式，最后指出归一化结果进入 `relative_drift` 列。由此读者能理解为什么出分率为 100%，漂移仍可能超出 0.25。若用假例，让原来在 0、1、2 的三名患者都向右移动 0.5。患者间距离完全保持，漂移仍约为原半径的 0.61 倍。例子只演示指标区别，正式结果和适用条件仍由原计算给出。

### 4. 以读者能否复述和回查作为交付检查

把 [references/delivery.md](../../skills/beta/bensz-rmd-rules/references/delivery.md) 的科学论证检查落实为一次成品审阅。先顺读渲染正文，复述主要结论、实际效应、关键反例和适用条件，再抽查正式字段、图表、阈值及实现。对复杂分析，保留简短的审阅记录，标出对应段落和发现的问题，修订后复读。特别检查两种容易在技术验收中漏掉的情况：小节标题声称回答两问，结果正文只回答一问；结论依赖选读报告或表格里的状态，主报告未说出结果对决策的含义。轻量报告可通过同样的复述和溯源完成检查。

确定性检查负责核对链接、正式数字、数学渲染、字段和入口。科学判断是否成立、措辞是否易懂、章节是否接住前文，留给成品审阅。发现正文遗漏时先补读或修订；正式汇总缺证据时，写明该项目前可下的结论和所缺观察。自然语言审阅和既有浏览器/计算检查即可承载这一改进。

## 实施范围与顺序

1. 在隔离工作区登记 `test-03` 的预设问题、代表性结果和当前正文位置，用固定汇总建立一份评审基线。再用随附配对分析覆盖简短报告，并构造有反例的结果快照。
2. 改写 `SKILL.md` 的相关步骤，分别更新 `references/report.md` 与 `references/delivery.md`。多篇报告各承担什么证据写在既有阅读顺序说明中。复杂案例用关键段落和正式代码片段示范如何从图表回溯指标。用户说明、版本和 CHANGELOG 随实际实现同步。
3. 用当前 Skill 与候选 Skill 做同输入、同模型、同输出要求的一次性交付对照，从全新上下文开始，只用固定汇总或经授权的等价快照。按相同评审问题判读实际 HTML；关键表现有波动时再加少量重复。仅改报告的场景另外从正式入口验证纯渲染复用，不重跑完整科研计算。

## 如何确认完成

| 场景 | 可观察的通过条件 |
| --- | --- |
| 复杂、多报告 | 从主报告正文能回答以下问题并指到段落：怎样区分直接秩与八维 PCA 的两种取舍？同癌种和跨癌种各差多少、区间多大、有没有通过已冻结门槛？为何都能出分且近邻重合较高，坐标仍不能在当前条件下按绝对位置解释？两份选读各提供哪项补充证据？复查主要结论时能定位对应的正式结果。 |
| 公式和解释对得上 | 至少抽查三元组的平局和共同分母，以及冻结坐标漂移。能从白话推导公式中每项代表什么，并与正式实现、分母、单位和舍入一致。选择一项存在重复角色的区间，核对重采样单位及区间条件。 |
| 代码能教会读者看懂图表 | 从渲染的主效应图和冻结包验收表各选一项，沿可见代码讲清输入、关键转换和图表数字的对应关系。能说明更换配对资格、对照方向或归一化分母会怎样改变读数。用同一份汇总做展示负例，仅保留 `selection_plot(effects)` 或 `dt(...)` 调用，页面可正常展示，代码解释项判为未通过。 |
| 含关键负例的报告 | 改变关键对照的方向、让区间越过实用门槛，或使一项关键比较因覆盖不足而不可估。在隔离输入上核对摘要、结果和决策文字是否随证据改变，且能识别同报告中样本出分率和题目可评分率的区别。至少保留一条可发现旧正文结论失效的反例。 |
| 简短单报告 | 随附配对示例三项内容可读可查：为什么比较配对变化、估计及区间是什么、为何难以外推到未随访单位或作因果解释。换无有效配对或缺失较多的输入时，报告状态和文字一并接受复核。 |
| 渲染与复用 | 桌面和窄屏可读公式、短表和链接。只改文字后复查有效 targets 的执行记录和正式结果，确认无估计重跑且关键数字、单位和分母保持一致。记录实际运行平台与未验证的环境。 |

## 待确认事项

现有成果可作为诊断和评测基线。固定汇总的对照检验写作与交付流程，完整的一次性分析生成是否遵循新指令，还需要日后用可控的小型项目实测。原报告还缺同患者独立技术重测及临床终点；文案修订能准确表达这些边界，实际扩大结论需另有证据。
