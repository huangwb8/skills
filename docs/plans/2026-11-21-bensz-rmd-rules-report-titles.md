# bensz-rmd-rules 报告标题与章节编号改进实施计划

## 通俗解释：究竟发生了什么

读者打开报告时，需要从页首知道这项研究在做什么，也需要在正文里快速找回某一节。拿 test-02 来说，主标题问「还剩多少基因，才能相信一个程序分数？」。只看这句话，读者还要猜是哪种分数、怎么算「相信」。三份报告虽然能按文件名排序，打开以后，正文各节却没有编号可供引用。

改进后，页首会直接说明这份报告研究乳腺癌数据中缺少部分基因测量时，程序分数可能偏离多少。正文则会显示「1 摘要」「2 引言」以及小节编号。三份报告的文件名仍用来标示阅读顺序。

## 专业判断：问题在哪里

test-02 三份 HTML 的 47 个正文标题均无节号。三份 Rmd 沿用项目自己的渲染入口，均省略了 `number_sections`。Skill 的生成器又只在 Liquid Glass 主题片段里开启这个选项，`plain` 和 `flatly` 缺少同一默认值。最小渲染已经复现三种情况：省略和显式关闭时均无节号，开启后正文显示 `1`、`2`、`2.1`。现行交付检查覆盖目录和文件编号，正文节号仍需单独核验。 [生成器](../../skills/beta/bensz-rmd-rules/scripts/new_project.py#L11) · [主题规范](../../skills/beta/bensz-rmd-rules/references/visuals.md#liquid-glass-html) · [交付检查](../../skills/beta/bensz-rmd-rules/references/delivery.md#先核对结果再读-html)

主标题的实质问题是把「固定参考 TSP」等研究信息留给了副标题，又用「才能相信」暗示通用阈值，超出了给定容差和固定参考条件下的误差分析。现行规范规定了报告语言和摘要结构，题名与研究内容的对应关系还缺少明确的审阅要求。现有材料不足以确定当时拟题的原因。 [报告规范](../../skills/beta/bensz-rmd-rules/references/report.md)

## 要达到什么目标

正式 HTML 的正文标题默认按层级显示节号。AI 根据实际研究对象、分析目标、设计和证据范围自主拟定题名。新建报告和沿用既有 Rmd 的项目都按各自的正式入口验收，用户或投稿模板明确规定的编号与题名要求优先。

本次实施限于 Skill 的报告写作与交付规范，以及示范骨架的编号配置。test-02 用于隔离验收，分析方法、数据处理和正式产物都保留在原项目。

## 改进方向

### 明确示例项目的用途

在 `SKILL.md` 中说明，`templates/project/` 提供一个可运行、可改造的起点。目录、文件名、代码、数据、分析方法和报告结构等全部内容均供参考。AI 可根据实际研究和项目现状选用、调整或跳过任一部分。统一的交付要求由 Skill 明文规定，在实际产物上验收。

### 把章节编号设为报告默认行为

- 在 `SKILL.md` 明确区分文件名的三级阅读编号、YAML 页首题名和 HTML 正文章节编号。前者标示多份报告的阅读顺序，后者由 R Markdown 和 Pandoc 按 Markdown 层级生成。
- 将 `number_sections: true` 放进配对骨架公共的 `output.html_document` 配置，从 Liquid Glass 专属片段移除。三个主题共用同一规则。用 `## 数据与方法`、`### 研究设计` 这类标题层级生成节号，避免在源码里手写编号和在成品里出现双编号。
- 在 `references/visuals.md` 与 `references/delivery.md` 补齐既有报告路径。任务涉及新写或修订完整报告时，检查其原有渲染入口是否生成节号，必要时补齐 Rmd 配置。用户或投稿模板明确规定关闭编号的情形采用对应设置。验收从成品中的正文标题、目录和跳转链接入手，同时保留项目原有的主题和入口。

### 让正式题名准确说明分析范围

- 在 `references/report.md` 写清起草和定稿的依据，由 `SKILL.md` 的报告撰写步骤引用。AI 根据实际研究对象、分析目标、设计和证据范围自主拟定题名，在主要结果确认后回核。队列、设计或关键方法能帮助界定范围时，可写进标题。句式根据实际内容选择。采用问句时，检查问题是否具体、报告是否实际回答。用户明确指定题名或文体时沿用其要求。
- 将页首题名与主要结果和结论核对，检查题名能否独立说明研究范围，以及是否把探索、模拟或单一任务验证写成普适结论。test-02 主报告可拟为「乳腺癌表达谱中固定参考 TSP 程序评分的基因缺失偏差与误差界」。历史架构页可用「乳腺癌表达谱的程序评分架构比较与跨队列稳定性评估」，读数页可用「乳腺癌表达谱程序评分的读数消融、ER 区分与技术重复评估」。

## 实施范围与顺序

1. 在 Skill 中写明示例的适用方式、章节编号规则和拟题依据，同步报告、主题与交付规范。
2. 将公共编号配置接入骨架，更新双语 README 与变更记录。
3. 用新建骨架、从零组织的报告和隔离的既有项目验证规则，按实际覆盖范围记录结果。

## 如何确认完成

- 用正式入口渲染 Liquid Glass、`plain` 和 `flatly` 骨架。正文一级和嵌套标题各有一个正确节号，页首题名独立显示。启用目录时，核对显示、节号和跳转链接。另验显式关闭编号，并在桌面和窄屏打开 Liquid Glass 检查节号是否可见。
- 在 test-02 的隔离副本上，先用现有配置复现失败，再仅改报告配置和题名，通过原入口重渲染。核对三份 HTML 的题名、节号和链接，并比对报告数值、正式结果和 targets 元数据。
- 用前后配对估计与外部队列验证等不同设计核验拟题能力。给出研究背景、比较和结果，由 AI 自主拟出准确且可区分的题名。至少一份报告从零组织或沿用既有项目结构，按成品核验编号和题名。
- 分别记录正式渲染、浏览器检查和题名语义审阅的结果，注明实测平台。

## 风险与待确认事项

test-02 的原入口依赖有效的计算结果。如果隔离副本无法复用，用同样的 YAML、主题和标题层级构造最小报告验证渲染行为。届时交付记录须标明实际覆盖的场景，完整项目原入口的回归仍待验证。
