# `skills/beta/bensz-rmd-rules` 重构计划

## 重构目标

让 `bensz-rmd-rules` 写出一份能顺着读、也能往回查的科学报告。读者打开 HTML，就能看懂为何要问这个问题、结果支持什么判断、这种判断在哪些条件下成立；想复核时，可以从图表追到关键代码，再找到正式分析的入口。改文字、图注或样式时，报告应复用仍然有效的昂贵结果。

以 `test-02` 为例，两份 HTML 已经算出了取舍所需的结果，但正文放了 21 张表，最有价值的比较要读者自己找，桌面上也有宽表撑开整页。改进后的报告会先解释「保留哪种读数，以及什么情况下改用另一条路径」，用一组精选图表说明差异，展示能帮助读者理解比较口径的代码，把完整明细留给需要继续核查的人。

**重构原则：守住证据和复现要求，把表达决策交给 Agent。** 同一套规则应能写出一页分析简报，也能支撑有多个科学问题的完整报告。

## 专业判断与范围

现有 Skill 已有可用的分析工程基础：simple 适合低成本流程；targets 适合昂贵、有多处复用或需要局部重算的流程；renv、受保护输入和正式入口支撑可复现。现有参考也已覆盖代码块解读和 DT 小组件，但报告层还缺少贯通的规则：如何围绕科学问题组织证据，如何独立决定代码是否展示和计算是否执行，以及何时把长表留在正文、移入附录或单独交付。默认模板依赖和重复检查也需要收敛。正则只适合提示可疑位置，实际报告才是质量验收的对象。

范围限于 `skills/beta/bensz-rmd-rules/` 的指令、参考、模板、辅助脚本、使用文档和必要回归。以 beta 0.30.3（`2013966`）为基线，保留 HTML 与 Rmd 同目录同名的默认值、已有项目不自动迁移和现有测试隔离。实施前在当前基线上定向复核[上轮冗余审查](2026-11-21-bensz-rmd-rules-冗余审查.md)涉及的行为。`test-02` 用作对照案例，候选报告在隔离副本中生成，复用已保存的汇总结果。

## 改什么

### 1. 围绕科学问题组织报告

动笔前，Agent 自主确定一项或多项值得回答、现有数据能够检验的问题，说明它们为何重要、影响什么判断，并区分主要、次要与探索性分析。为每个主要问题安排比较对象、证据和结论边界。若证据只够回答较窄的问题，就缩小问题或明确未能回答的部分。

正文可以先给出主要发现和取舍，再按问题展开：为什么选这个比较，怎么算，观察到了什么，这些结果能支持多强的判断。代码交代关键决定，图展示模式、差异和不确定性，表提供需要精确查读的数字，文字把证据和判断连起来。关键解释按研究设计报告效应大小、比较口径、分母和不确定性，并交代有实际影响的限制、反例或替代解释。比如，讨论两种读数能否互换时，可展示如何构造配对样本，配上差异图和关键分层的汇总表，再解释哪些差异足以改变实际决策。图、表和代码的数量由问题与读者决定。四层框架保留为写作提示，取消最低观察句数、固定后续动作数等默认门槛。

### 2. 分开规划代码展示和计算执行

Agent 在拟定报告结构时，同时为关键步骤决定两件事：读者是否需要看这段代码；每次渲染是否有必要执行它。这个判断由代码的解释价值、计算成本、复用需求和结果失效条件决定。

| 步骤 | 报告里怎样呈现 | 在哪里执行 |
| --- | --- | --- |
| 影响结论且开销很小的比较、汇总或诊断 | 展示足以解释分组、分母、比较口径或指标定义的代码；较长时可折叠 | 放在适合的正式入口。complex 的 Rmd 可以轻量整理正式结果，影响估计的逻辑仍在分析端 |
| 耗时拟合、重采样、难以重复的外部结果，或已经有效生成且无需重算的步骤 | 需要时展示真实实现的简短片段或链接，说明它如何产生当前图表 | 在正式计算入口执行，报告读取已经验证的结果；complex 复用 targets，由实际数据、参数和代码依赖决定失效 |
| 包加载、路径配置和重复的排版代码 | 保留在源文件，默认不展示给读者 | 按渲染需要执行，避免在报告里安装依赖或附带有副作用的分析 |

隐藏一个代码块不会阻止它运行。`echo = FALSE` 只控制显示；供读者参考但不执行的片段可用 `eval = FALSE`，并注明其对应的正式实现和结果来源。可复用结果需要能追到代码、输入、分析参数及重建入口。缺失或失效时，由正式入口生成或给出明确原因；报告不静默重跑，也不使用无法确认来源的旧结果。低成本的 simple 仍可直接重建。已有项目如果具备可追溯的结果读取路径，可以沿用；需要接入 targets 时另行决定是否迁移。

### 3. 让长表能查、宽表不撑开页面

短表和支持主要判断的少量比较，在正文中用清楚的静态表。对需要反复查找的长表、宽表或多列比较，HTML 优先考虑 `DT::datatable()` 或现有辅助函数，按内容选分页、搜索、排序或表内横向滚动。表头、单位、精度和缺失值的写法要让读者能直接读懂，并在最终 HTML 中确认表格确实可见、表内滚动不会推宽整页。

正文给精选结果和解读，较长明细放附录或交付为可链接的文件。分页不会减少静态 HTML 内嵌的数据量；特别大的数据先判断筛选哪些行列、是否需要提供单独的完整交付。现有 `render_dt()` 默认只保留前 100 行，若用它做预览，应标注显示范围及选取依据，并在允许交付完整明细时给出入口。交付样例应体现何时该用 DT；小报告无需引入 DT，没有交互能力的输出可用静态摘要和明细附件。

### 4. 让模板、参考和检查器各自好维护

simple 和 complex 都提供能独立渲染的普通 HTML 起点。前者展示一条低成本分析，后者展示如何读取 target 结果并生成报告；另给按需启用的长表案例。Liquid Glass、DT、图形风格和 PDF 预览由交付需求选择；启用时复制齐全，视觉预览与正式渲染分开。把依赖安装放回初始化和显式恢复，正式运行使用锁定环境；清理没有消费者的默认包和计算入口的字体探测。保留已有项目自己的入口、目录和主题。PDF 预览只维护一个转换路径，并核验含空格路径。

- **合并重复说明。** `SKILL.md` 保留科学问题、分析入口、报告决策和交付审阅的核心要求；参考按模式与重建、推断与报告、测试与交付收敛。清单引用规则，README 说明用法。优先重用现有的代码块、解读和表格参考，保留能说明取舍的少数实例。
- **收敛配置与脚本。** 先用入链和实际读取核对配置、模板、检查器。删除没有消费者的键、空示例和只返回说明的 DAG 节点。将项目状态与报告依赖预检的共同逻辑放一处；保留明确有作用的 widget 检查、文件和路径检查。现有公开 CLI 可以共用实现。
- **降低启发式检查的权重。** 文本检查默认提示，能指出疑点和位置即可。正式交付以结果核对和渲染审阅为准。对 `--mode` / JSON `mode` 等废弃接口，先查本地与已知外部消费者；证据不足就保留薄别名并标记退役，公开文档统一推荐 `--project-state`。

## 如何确认完成

- **读完整篇报告，复核代表性结论。** `test-02` 能解释为何保留 TSP、为什么不能宣称冻结分数普遍可互换、ER 预测为何应单独选型，以及何时使用带标记的补全。抽查正文中的数字、分母、区间和适用范围，沿展示的代码或链接找到实际汇总与正式计算来源。简短报告按同样的证据标准判断，无需凑章节或图表。
- **验证代码展示与重算边界。** 在隔离副本里只改文字或样式并重新渲染，用 targets 元数据和执行记录确认昂贵阶段没有重跑、结论数字不变；再改变会影响结果的分析输入或参数，确认正式入口更新受影响的结果。模拟成果缺失，确认报告给出可操作提示，正式入口能补齐。检查 Rmd 和 HTML，确认可见代码确实解释了关键判断，且没有把隐藏执行误当成跳过执行。
- **在实际浏览器里用表。** 在桌面和窄屏打开长表案例，实际操作分页、排序、搜索和宽表的局部滚动（按启用功能验收）；核对静态摘要的数值、预览标记和完整明细入口。缺表、截断却声称完整，或整页被撑宽都视为失败。
- **跑兼容与负例。** 轻量测试使用同一正式入口。simple 在无 targets、无 DT、无主题和无任务工作区依赖时仍可渲染；complex 用随附模板消费同一 DAG 的结果。显式恢复成功后，核对支持离线的正式分析路径；缺少已声明依赖时说明原因。已有项目检查不生成新骨架。按承诺的能力和实际变更范围核验中断恢复、隔离副本迁移、含空格路径及可选主题；未跑的场景和平台分别标明。

瘦身用改前改后的参考数、配置体量和默认模板依赖数辅助核对。发布判断以实际交付和回归为准。若某项合并会破坏已有调用，优先保留兼容入口；若一条提示不能改善报告或发现实质错误，删除它或移到可选参考。
