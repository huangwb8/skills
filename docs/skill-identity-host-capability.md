# Skill 身份：Codex 候选宿主能力报告

## 已取得的证据

2026-11-14 在 macOS 使用真实 `codex-cli 0.153.4` 的 `app-server --stdio`，以独立临时 CODEX_HOME 和合成项目调用 `initialize`、`skills/list(forceReload=true)`。没有调用模型、读取用户凭据或安装系统 Skill；仅保留合成 fixture 的结构化字段。

无 config、无签名的 `.agents/skills/unsigned-identity-probe/SKILL.md` 被发现，其公开合成 description 出现在响应中。增加用户级同名 fixture 后，响应同时列出 `repo` 和 `user` 两个 scope 的同名条目。因此该发现入口没有以本协议验签作为返回描述的前置条件；同名候选可同时暴露。没有观察真实模型如何选择和加载它们，不能把列表顺序推断为遮蔽优先级。

脱敏原始结果位于本任务 `shared/output/host-probe/{result,shadow-result}.json`。CLI 版本、协议 Schema 生成和真实响应属于实际宿主证据；身份库 fixture 测试属于本地程序证据，两者分别验收。

| 检查后替换、并发更新和运行中撤销的宿主门禁 | 未验证 | 库的重验不代表宿主执行边界重验 |
| router 结构化依赖接入 | 未实施 | 独立仓库后续任务 |

当前产品保证限定为 `files_verified`。依赖锁、内容快照和严格安装提供基础能力；宿主若自动读取其它目录、已进入模型历史的文本或未覆盖的工具路径，仍超出该保证。签名不会增加进程、文件或网络权限。

## 后续接入契约

适配器应在描述/正文进入受控候选上下文前解析精确要求并验证；消费独立快照，在实际读取/执行边界重验撤销与内容，记录锁摘要与真实加载字节的绑定。要求为结构化 `skill_requirements` 数组，每项遵循协议的精确要求；router 客户端本地解析并保留锁，服务端只持有公开 ID 与摘要，不上传任务或路径。受保护流程只补充已下发步骤的要求。

验收需要真实宿主的加载与工具事件，而非 Agent 自报、提示词要求或只读权限。受控入口尚未取得这类证据，因此本轮不宣称接入版或端到端防护完成。
