# 机器味写作模式参考

只改表达，不改事实。按词语→句法→段落→章节扫描；专业术语不因英文或代码出现而自动删除。

## 词语与常见句式

| 模式 | 处理 |
| --- | --- |
| 首先/其次/最后、因此/从而/进而连环使用 | 直接给判断，再补关键原因 |
| “随着发展”“广泛关注”“重要理论意义” | 点出现有约束、缺口或具体解决对象 |
| “来源/支撑/抓手/赋能/闭环”等抽象标签 | 改成原文已有的筛选、验证、比较、解释、评估或收敛动作 |
| 括号套括号、长分号串、机械“研究表明…\cite{}” | 拆成句流；合并承担同一证据角色的判断 |
| “不是 A 而是 B”“不只是 A 更是 B”等 | 真边界保留并弱化；伪对立把 B 放入主干；同义递进合并，不补事实 |
| “值得注意的是”“需要指出的是”、保持沉默、只是多想一次 | 直接写研究判断；纯姿态或模型自我辩护合并/删除 |

## 工程协议腔与规格书句法

- 入口/出口、状态映射、队列、载荷、闸门、终态、整包、静默补写、失败码等词连续出现时，恢复研究主体和动作；确属实现细节则保留并首次中文释义。
- 同句用分号、括号或八步以上箭头同时列动作、配置、版本、失败和验收时，先保留会影响复现的字段，再按研究内容/方法/质控职责拆分；字段若含阈值、权限、分母或失败处理不得删除。
- 连续“归入、映射、锁定、冻结、收缩、降级”却无研究人员、评分者、数据管理员或系统作主语时，补回原文已有主体，不新增职责。

## 术语与语域

| 类型 | 处置 | 示例 |
| --- | --- | --- |
| 受控术语 | 逐字保留 | `\texttt{RELEASE}`、`H_0`、统计量、模型名、接口字段 |
| 可保留术语 | 首次中文释义，后文用稳定短称 | `manifest`、`fail closed`、参考包络 |
| 临时造词 | 优先改写；对象不确定则人工确认 | 四态终结、有界使用政策原型、纯暴露解释 |

混合语域采用“中文总括 + 必要英文括注”，不得改代码、数学、引用或状态 token。专业技术细节本身不是机器味。

## 章节去重与处置

- 建立“事实—首次完整定义—后续引用”表；冻结、污染、样本和边界规则只在一个章节完整说明，其他章节保留本节必需短句；疑似有意重复则人工确认。
- 每个候选项标为 `保留`、`改写`、`合并` 或 `人工确认`，写明理由和不可改变的含义。
- 目标写“要达到什么”，研究内容写“怎么推进”；立项依据重问题/缺口，研究基础重证据链，工作条件重资源对位，风险应对重风险—触发—影响—备选。

## 安全不变量

只记录原文已有的状态/权限、阈值、分母、暂停/失败处理、探索性定位和规划资源边界。改写后做“原句—改写句—不变量”对照；无法证明时保留原句。

## 结构保护

`\cite{}`、数学公式、`\ref{}`、`\eqref{}`、环境、`\item`、注释和列表 token 必须逐字保持。
