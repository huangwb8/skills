# 输出与缓存契约

## 目录职责

`output.dir` 只放用户要消费、解释或交付的稳定文件；`cache.dir` 放可由声明输入重建的中间产物。两者分离能让用户清理缓存而不误删结果，也能让程序用更激进的缓存布局而不污染交付目录。

建议约定：

- 参数为 `NULL` 时不落盘，只返回内存对象。
- 路径由调用者传入；库函数不依赖 `getwd()` 推断持久化位置。
- 创建目标父目录，但不接管其上级目录。
- 默认 `overwrite = FALSE`；覆盖只作用于函数声明的已知目标。
- 返回值携带 `artifacts$output` 与 `artifacts$cache`，而不是要求用户猜文件名。

## 缓存身份

缓存 key 至少绑定：输入内容或稳定摘要、影响结果的参数、算法/格式版本和必要的上游产物身份。不要只用文件名或修改时间。缓存读取失败、schema 不符或 key 不匹配时重算当前条目，不递归删除整个缓存树。

## 原子写入

在目标目录写临时文件，关闭连接并确认可读后再 rename 到最终路径。同一文件系统内 rename 通常是原子的；覆盖时只删除显式目标。并发写同一 key 时使用成熟锁实现（如 `filelock`）或让每个 worker 写唯一文件，由主进程汇总。

## Manifest

多文件结果建议写 manifest，至少包含相对路径、类型、输入摘要、参数、seed、生成时间和格式版本。最终写 manifest/成功标记，避免把半成品误认为完成。

## 安全边界

规范化路径并确认位于授权根目录。不要把 token、完整环境变量、个人路径或大体积原始输入写入日志和 manifest。未经明确授权，不清理未知文件或非本函数创建的目录。
