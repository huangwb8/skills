# bensz-rmd-rules

## 目标

用 R 把有价值的科学问题写成可复核的论文式报告。让非专业读者理解发现，让专业读者能从判断追到数据、公式、代码和重建入口。仅渲染现有 Rmd 用 `knit-rmd-html`，主要交付可复用 R API 或包用 `bensz-r-developer`。

## 流程

### 输入

核对读者、待做的决定、研究设计、输入、授权及现有入口、环境、结果和报告。区分用户决定、研究方案、探索性选择。先推进可检验部分，缺口会改变关键口径或授权时再询问。

### 执行步骤

1. **界定科学问题。** 写明哪些证据会改变判断，明确人群、单位、对照、效应尺度，区分主要、次要及探索性问题。按设计处理分母、缺失、依赖结构和不确定性，按证据限制结论。[推断与报告](references/report.md)
2. **用 `targets` 正式计算，用 `renv` 锁定环境。** 按科学阶段声明真实输入、参数、函数和环境依赖，完成清洗、样本定义、估计、诊断和稳健性分析。Rmd 在锁定环境读经核验的结果。既有框架沿用原入口，需从无框架项目另做交付时用独立目录接入授权输入。新项目可按需取用、调整或跳过[骨架](scripts/new_project.py)的任何部分。[计算、环境与重建](references/workflow.md)
3. **完成论文式论证。** 每份新分析交付结构式摘要、引言、数据与方法、按问题组织的结果、质控与数字核对、讨论和可复现性说明。先做主要分析，再按风险补会影响判断的诊断或比较，讨论交代未决问题。YAML `title` 写清对象与范围，结果确认后[复核题名](references/report.md#正式题名)。撰写或改写摘要时依次写四个明确标注的部分：背景、方法、结果、结论。局部维护遵守授权范围。[完整报告](references/report.md#把完整研究写成论文式报告)
4. **把方法、实现和解读连起来。** 主要代码前说明数据、方法和目的。实际分析和绘图代码默认展开，长实现可折叠。报告执行取数、核对、绘图与排版。结果解读、讨论和摘要结论直接写在 Markdown 正文，内联 R 只带入事实。难懂概念可用标明性质的假设例子和与计算一致的公式。[代码与数字](references/report.md#代码怎么展示数字怎么引用)
5. **验收成品与重建。** 回查主张、数字和质控证据，打开 HTML 看公式、代码、图表、窄屏及链接。新建或改动计算流程时，在隔离副本用合成输入或授权子集走同一正式入口，按风险验收复用、失效、恢复和重建。[测试与交付](references/delivery.md)

### 输出

交付 Rmd、同目录同名 HTML（默认）、分析代码、锁定环境与需保留的结果及明细。提供环境恢复、正式重建和适用的单独渲染命令，注明启动位置、结果来源和实测范围。报告语言按用户要求或任务所用语言，图表默认英文并接受明确覆盖。[图表语言](references/visuals.md#图表语言)

### 输出管理

按需使用 `raw/`（受保护输入）、`products/`（科学结果）、`reports/`（图表与补充交付）、`_targets/`（可重建计算存储）。测试副本放独立测试目录，草稿、审阅与日志归任务工作区。

多份独立报告默认用 `01.01.01-` 三级阅读编号，Rmd 与 HTML 同名，README 顶部按编号链接 HTML，标出主报告与选读项。单报告可省略前缀，既有文件优先用索引指路。[多报告的阅读顺序](references/delivery.md#多报告的阅读顺序)

新建 HTML 默认 Liquid Glass。已有报告沿用主题和入口。新写或修订完整报告时，页首单显 YAML 题名，正文按 Markdown 层级自动编号，遵从用户或投稿模板的明确设置。[主题与章节编号](references/visuals.md#html-章节编号)

### 校验

验算关键结论、正式数字与图表，检查代码前有分析理由，成品可直接读关键代码。质控写出实际状态、异常影响与处置，讨论处理能改变判断的缺口。改计算或数字引用时，在隔离副本改变相关输入并核对正文和图表同步变化。复杂项目改报告文字时核对有效估计未重算。分别报告预检、轻量运行、全量运行和真实浏览器验收。

### 失败与恢复

缺依赖时给恢复步骤，缺失或失效的结果由正式入口补齐。报告入口禁止隐式安装、拟合或吞错。只有固定汇总时，将快照和来源纳入流水线，说明验证范围、原分析追溯办法及无法核实的条件。不可估计或未运行的比较写明原因。

### 公共硬约束

本块由 `docs/templates/skill-common-constraints.md` 统一维护；每个 `SKILL.md` 的 `## 约束` 必须逐字同步本块，不得在副本中改写公共规则。

- 任务需要落盘时，使用唯一的 `./.bensz-api/task-{yyyymmdd-hhmm}-{简短描述}/` 根目录；共享材料放入 `shared/`，Skill 专属材料放入该 Skill 的 `input/`、`output/`、`log/`。
- 正式交付物、源代码和正式计划按项目约定保存，不写入任务工作区；未经授权不覆盖、删除、迁移或远程写入。
- 项目维护变更检查 BAC 可用性并记录需求、AI 产出、工具结果、文件改动和验证摘要；BAC 只做过程审计，不替代署名、责任或合规判断。
- 不记录 API Key、访问令牌、密码、Cookie、环境/凭据文件、私有 Prompt、身份信息、本地用户名、主机名或不必要的大体积原始数据。
- 文件路径必须规范化并限制在授权项目范围内；外部 URL、子进程和网络访问遵循最小权限，防止路径遍历、SSRF 和命令注入。
- Skill 版本唯一记录在自身 `config.yaml:skill_info.version`；公开 API、协议、目录或配置变更同步文档与 `CHANGELOG.md`。
- `bensz-collect-bugs` 是一个 Agent Skill；仅将 Bensz Agent Skill 或 Bensz 基础设施本身的设计缺陷交给它。先脱敏写入 `~/.bensz-skills/bugs/`，当前任务不中断，只有用户明确要求才公开上报，禁止直接修改用户已安装的 Skill 源码。

### Skill 专属约束

- 原始数据、不可再生标注和唯一外部快照保持只读。输入、计算状态及交付相互独立。测试只在隔离副本运行，禁止清理正式 store 或用测试开关替换估计算法。
- Rmd 展示的表格均用 `DT::datatable()`，包括正文汇总与附录明细。短表可关闭搜索、排序及分页。[报告表格规范](references/report.md#用-dt-展示报告表格)
- 汇总展示授权不包含个体数据。检查 HTML、widget 和附件的授权，分页不会减少客户端收到的数据。
