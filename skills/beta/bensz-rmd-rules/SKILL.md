# bensz-rmd-rules

## 目标

用 R 完成可复现的深度分析。让读者理解判断，并能回查数据、公式、代码和重建入口。

## 流程

### 输入

核对读者、决定、设计、输入、授权、现有入口、环境、结果和报告。区分用户要求、预设与探索。先做可检验部分，关键口径或授权不明时再询问。

### 执行步骤

1. **界定科学问题。** 列出影响主要决定的判断、来源、比较及分析单位、证据位置和结论边界。区分开发、留出确认、部署检验和探索诊断，明确人群、尺度、分母、缺失、依赖和不确定性。[推断与报告](references/report.md)
2. **正式计算与环境。** 用 `targets` 声明输入、参数、函数和环境依赖，分阶段清洗、定义样本、估计、诊断和验证稳健性。Rmd 在 `renv` 锁定环境读取已核验结果。沿用已有入口，无框架时在独立目录接入授权输入，新项目可取用、调整或跳过[骨架](scripts/new_project.py)。[计算、环境与重建](references/workflow.md)
3. **完成论文式论证。** 新分析写摘要、引言、数据与方法、按问题组织的结果、质控与数字核对、讨论及可复现性。先做主要分析，再补影响判断的诊断。并列效应、区间、门槛和判断，说明未运行、不可估、偏离方案及其他证据边界。YAML `title` 写清对象与范围，结果确定后[复核题名](references/report.md#正式题名)。新写或改写摘要依次标明背景、方法、结果、结论。局部维护遵守授权。[完整报告](references/report.md#把完整研究写成论文式报告)
4. **用能逐步运行的代码展示结果。** 用白话或手算假例引出难点的正式定义。主图展示绘图数据、字段和实际绘图代码。关键表格展示决定读数的计算。核心模型展示样本构建、实际参数、训练和内验证。默认展开关键片段，交代运行前需要的对象和设置，让读者能逐步运行并检查中间结果。共用逻辑可链接到报告内展示的位置，渲染复用已核验的正式结果。内联 R 引用事实，解读、讨论及摘要结论直接写入 Markdown。[代码与数字](references/report.md#代码怎么展示数字怎么引用)
5. **验收与重建。** 顺读 HTML，复述判断、量级、反例及边界，回查正式结果与实现，修改后复读。在桌面和窄屏查公式、代码、图表及链接。新建或改动计算时，用隔离副本和合成输入或授权子集走正式入口，按风险验证复用、失效、恢复和重建。[测试与交付](references/delivery.md)

### 输出

交付 Rmd、同目录同名 HTML（默认）、分析代码、环境锁及需保留的结果与明细。给出启动位置、环境恢复、正式重建和适用的单独渲染命令、结果来源及实测范围。报告语言随用户要求或任务，图表默认英文，可明确覆盖。[图表语言](references/visuals.md#图表语言)

### 输出管理

按需使用 `raw/`（受保护输入）、`products/`（科学结果）、`reports/`（图表与补充交付）、`_targets/`（可重建计算存储）。测试副本放独立测试目录，草稿、审阅与日志归任务工作区。

多份独立报告默认用 `01.01.01-` 三级阅读编号，Rmd 与 HTML 同名，README 顶部按编号链接 HTML。主报告给出主要证据及边界，选读说明补足的证据并互链对应小节。单报告可省略前缀，既有文件优先用索引指路。[多报告的阅读顺序](references/delivery.md#多报告的阅读顺序)

新建 HTML 默认 Liquid Glass。已有报告沿用主题和入口。新写或修订完整报告时，页首单显 YAML 题名，正文按 Markdown 层级自动编号，遵从用户或投稿模板的明确设置。[主题与章节编号](references/visuals.md#html-章节编号)

### 校验

验算主张、正式数字和图表。从成品回查主图的输入到绘图、主表的输入到读数、核心模型的样本到训练与内验证，确认可见代码对应本次结果。说明质控状态、异常影响与处置及未决问题。改计算或数字引用时，用隔离输入验证正文、图表同步变化。复杂项目只改正文时核对有效估计未重算。分别报告预检、轻量运行、全量运行和浏览器验收。

### 失败与恢复

缺依赖时给恢复步骤，缺失或失效结果由正式入口补齐。报告禁止隐式安装、拟合或吞错。固定汇总纳入流水线，说明来源、追溯办法、验证范围及缺口。未运行或不可估的比较写明原因。

### 公共硬约束

本块由 `docs/templates/skill-common-constraints.md` 统一维护；每个 `SKILL.md` 的 `## 约束` 必须逐字同步本块，不得在副本中改写公共规则。

- 任务需要落盘时，使用唯一的 `./.bensz-api/task-{yyyymmdd-hhmm}-{简短描述}/` 根目录；共享材料放入 `shared/`，Skill 专属材料放入该 Skill 的 `input/`、`output/`、`log/`。
- 正式交付物、源代码和正式计划按项目约定保存，不写入任务工作区；未经授权不覆盖、删除、迁移或远程写入。
- 项目维护变更检查 BAC 可用性并记录需求、AI 产出、工具结果、文件改动和验证摘要；BAC 只做过程审计，不替代署名、责任或合规判断。
- 不记录 API Key、访问令牌、密码、Cookie、环境/凭据文件、私有 Prompt、身份信息、本地用户名、主机名或不必要的大体积原始数据。
- 文件路径必须规范化并限制在授权项目范围内；外部 URL、子进程和网络访问遵循最小权限，防止路径遍历、SSRF 和命令注入。
- Skill 版本唯一记录在自身 `config.yaml:skill_info.version`；公开 API、协议、目录或配置变更同步文档与 `CHANGELOG.md`。
- `bensz-collect-bugs` 是一个 Agent Skill；仅将 Bensz Agent Skill 或 Bensz 基础设施本身的设计缺陷交给它。先脱敏写入 `~/.bensz-skills/bugs/`，当前任务不中断，只有用户明确要求才公开上报，禁止直接修改用户已安装的 Skill 源码。

### Skill 专属约束

- 原始数据、不可再生标注和唯一外部快照保持只读。输入、计算状态及交付相互独立。测试只在隔离副本运行，禁止清理正式 store 或用测试开关替换估计算法。
- Rmd 展示的表格均用 `DT::datatable()`，包括正文汇总与附录明细。短表可关闭搜索、排序及分页。[报告表格规范](references/report.md#用-dt-展示报告表格)
- 主图、关键表格和核心模型须展示或就近链接报告内实际生成结果的关键代码，并说明如何在授权环境中逐步运行。仅加载成图、打印已算好的对象或展示无法看清生成逻辑的封装调用，不满足此要求。上游确实不可查时，展示可查的步骤并标明断点。[代码展示规范](references/report.md#代码怎么展示数字怎么引用)
- 汇总展示授权不包含个体数据。检查 HTML、widget 和附件的授权，分页不会减少客户端收到的数据。
