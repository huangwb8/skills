# 测试与交付

## 多报告的阅读顺序

一次交付有两份或更多独立报告时，新报告默认用 `01.01.01-topic.Rmd` / `01.01.01-topic.html` 这样的文件名。每级两位、从 `01` 起，编号在本次报告集中唯一。比较两份报告时，从左往右看第一处不同的编号，较小的先读；相同的前缀越长，讨论的问题越接近。按读者需要了解的内容来排：先读当前主报告，再读支撑它的方法、补充证据或历史分析。

| 层级 | 什么时候换号 | 例子 |
| --- | --- | --- |
| 第一级 | 转到另一个主要研究问题或分析群 | 从当前的缺失误差研究转到历史架构比较：`01.01.01` → `02.01.01` |
| 第二级 | 同一主要问题下，转到另一条可以独立阅读的证据线 | 从架构比较转到单独成篇的外部验证：`02.01.01` → `02.02.01` |
| 第三级 | 继续读同一条证据线中的下一份报告 | 架构比较之后再看它的消融与方法明细：`02.01.01` → `02.01.02` |

在项目 README 顶部放阅读索引，按编号列出报告标题和 HTML 链接，标明从哪份开始、哪些报告可以按需阅读。读者能凭文件名排序，也能在索引中判断下一份是否有用。单报告、嵌在同一 HTML 内的附录、图表与数据附件无需编号；同组只有一份时保留 `01`，无需为填充层级拆报告。`targets` 继续按计算依赖运行，报告编号只用于阅读导航。

维护已有文件时，优先沿用已公布的路径，在索引里给出编号和阅读顺序；用户同意改名时，同步更新渲染入口、配置、复现说明、交叉链接和相关测试。验收时核对索引顺序、编号唯一性、新报告的 Rmd/HTML 同名配对；从 README 打开各报告，并检查受影响的交叉链接和渲染入口是否仍指向正确文件。

## 先核对结果，再读 HTML

完整报告交付前逐节回读摘要、引言、数据与方法、主要结果、质控和讨论。对每条核心主张检查：结果前有实际方法和理由，图表后有结合本次数字的解读；讨论交代结果限制和可能改变判断的条件。重要诊断或稳健性比较没有执行时，报告原因和影响。质控项核对实际状态、偏差及处置；可用一项无效输入或不一致结果的隔离反例检查报告能否诚实回报或停止。篇幅验收以论证完成度为准。

在 Rmd 和渲染后的 HTML 中检查本次撰写或改写的摘要。四个标签应按背景、方法、结果、结论的顺序出现，每部分承担[相应的内容](report.md#结构式摘要)。核对摘要的主要数字和不可估计状态是否与正文及正式结果一致。确认摘要结论与正文解读直接写在 Rmd 的 Markdown 中，并根据实际证据回答研究问题。

从结论中选会影响决策的数字，回查实际计算结果并按原口径验算：分析单位、有效分母、过滤、效应方向、区间和舍入。明确哪些结果支持判断，哪些只提示关联或需要验证。审阅成品中的表达、图例、轴、单位、色彩和图区；代码折叠及附件应可达，窄屏内容能读。确认所有展示的表格都由 `DT::datatable()` 渲染，实际操作已启用的搜索、排序、翻页和表内横向滚动；若无浏览器，注明未验证交互。

对关键解释做两次回读：顺着文字和日常例子，能否说出在比较什么、发现了什么与缺什么证据；顺着公式，能否找到相同的分析单位、分母、方向和假设，以及实现它的代码。核对类比中的数字没有混入研究结果，公式在最终 HTML 中能读，重要符号和公式引用没有因窄屏丢失。

抽查主要结果的顺序：代码前有方法理由，关键代码打开 HTML 就可读，代码后的数字来自同一个正式结果对象。改动分析或报告中的数字引用时，在隔离副本换一个能改变结论所引数字的输入或参数，用正式入口重建，核对正文、图表和不可估计状态按预期变化；仅修改解释文字时，核对仍有效的正式估计未重算。

针对渲染故障，先检查包、Pandoc、路径和 HTML 控制台。widget 缺失先看 chunk 有没有返回可显示的对象，以及是否被错误地包装在循环或折叠容器里。文本和源码扫描可以定位疑点；数值和交付质量以真实结果与成品为准。

核对成品正文是否采用预期的报告语言，并按[图表语言约定](visuals.md#图表语言)检查图注、标签、正文和附录表格中的表头及状态文字。

## 验证真实重建

使用项目副本，带合成 fixture 或最小授权子集；保护源项目、输入和正式 store。只替换输入规模和运行目录，保持正式入口、参数流和算法。使用能覆盖主要组别、缺失或依赖结构的例子。在授权范围内对输出值、键或科学不变量做断言，另查 HTML 实际存在。

按改动选择可区分成功与失败的场景：

- 冷重建：不带派生结果运行正式入口，按预定容差验证关键值与结构。
- 报告重渲染：只改正文、图注或样式，再运行报告入口。核对数值一致和 targets 计算记录未更新；不要只凭 HTML 修改时间。
- 失效与补齐：同路径换输入、修改分析参数或移走一个结果；报告明确拒绝失效结果，正式构建补齐并复用其余有效阶段。
- 可移植与恢复：项目移到含空格的目录，从锁文件恢复；需要时模拟中断、离线或新平台。只在测试副本移走产物或环境；涉及真实中断就记录触发位置及重跑证据。

给出实际命令、通过的断言、失败原因和未运行场景。轻量执行、全数据执行、浏览器验收和平台检查分别报告。

## 主题和图件验收

按[主题与图表规范](visuals.md)检查实际 HTML 和独立图件。对使用 Liquid Glass 的报告，在桌面和窄屏检查目录导航、代码展开与复制、图片放大；宽表须检查表头与表体对齐和表内滚动。单独交付的静态图由正式入口导出矢量 PDF。在任务工作区生成并打开位图预览，核查成品字号、裁剪和对比度；没能打开时记录未验证的部分。
