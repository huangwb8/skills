# 测试与交付

## 多报告的阅读顺序

两份及以上独立报告时，新报告默认同名 `01.01.01-topic.Rmd` / `01.01.01-topic.html`。每级两位、从 `01` 起，编号在本次交付内唯一。按首处不同编号由小到大读，共同前缀越长，问题越接近。主报告先读，方法、补充证据与历史分析随后。

| 层级 | 换号条件 | 例子 |
| --- | --- | --- |
| 一级 | 换主要问题或分析群 | 缺失误差 → 历史架构比较（`01.01.01` → `02.01.01`） |
| 二级 | 同一主要问题下换独立证据线 | 外部验证单独成篇（`02.01.01` → `02.02.01`） |
| 三级 | 同一证据线的下一份报告 | 架构对比后读消融与方法明细（`02.01.01` → `02.01.02`） |

README 顶部按编号列标题和 HTML 链接，标明先读和选读。单份报告、内嵌附录及图表附件可省略编号；独占一组时保留 `01`，无需拆分凑数。编号只影响阅读顺序，`targets` 按依赖运行。

沿用已公布的路径并从索引指路。经用户同意改名时，同步入口、配置、复现说明、交叉链接和测试。验收编号唯一、索引顺序和 Rmd/HTML 同名，逐篇从 README 实际打开，核对受影响链接与入口。

## 先核对结果，再读 HTML

- **题名与节号。** 独立读成品页首，再按[题名规范](report.md#正式题名)与主要结果核对，特别留意探索、模拟及单一任务验证的范围。新写或修订完整报告时，从项目原入口渲染，在桌面和窄屏检查题名独立显示、正文及嵌套标题各显示一次正确节号，以及启用目录时的层级、节号、跳转。明确关闭编号时检查正文和目录均符合要求。
- **科学论证。** 逐节回读完整报告。核心主张应有实际方法和理由，图表后有结合本次数值的解读，讨论交代能改变判断的条件。重要诊断未运行时交代理由及影响。核对质控状态、偏差与处置，必要时用隔离副本的无效输入或不一致结果检查是否如实报告或停止。以论证完成度验收篇幅。
- **摘要与数字。** 在 Rmd 和 HTML 核对本次改写或新写的摘要四标签、顺序及[职责](report.md#结构式摘要)。正文和摘要中的判断直接写于 Markdown。主数字和不可估计状态与正式结果一致。挑会影响决策的结论验算单位、分母、过滤、方向、区间和舍入。明确证据可支持的判断、仅提示的关联和待验证的解释。
- **解释与代码。** 顺读正文和例子复述比较、发现及证据缺口，沿公式回查单位、分母、方向、假设和代码。假设数字与真实数据分明，公式和符号在窄屏可读。检查主要代码前有理由、关键块默认可见、块后数字共用正式对象。
- **变化与故障。** 改计算或数字引用时，在隔离副本换能影响结论的输入或参数，经正式入口确认正文、图表与不可估计状态按预期更新。只改解释时核对有效估计未重算。渲染失败先查包、Pandoc、路径和控制台，widget 缺失先查 chunk 是否返回可显示对象及循环/折叠容器。源码扫描用于定位，验收依据实际结果和成品。

## 验证真实重建

隔离副本使用合成 fixture 或最小授权子集，保持正式入口、参数流与算法，只缩输入规模并换运行目录。样例覆盖主要组别、缺失或依赖结构；在授权范围内断言值、键或科学不变量，另查实际 HTML。按改动选择区分成功与失败的场景：

- **冷重建。** 无派生结果运行正式入口，按预定容差核对值和结构。
- **报告重渲染。** 只改正文、图注或样式，运行报告入口，核对数值和 targets 计算记录。HTML 修改时间不能充当复用证据。
- **失效补齐。** 同路径换输入、改参数或移走结果。报告拒绝失效结果，正式构建补齐并复用有效阶段。
- **可移植与恢复。** 移到含空格路径，按锁恢复，按需模拟中断、离线或新平台。只在测试副本移走产物或环境，真实中断记录触发位置和重跑证据。

交代命令、断言、失败原因和未运行场景，分别报告轻量执行、全数据执行、浏览器验收及平台检查。

## 主题和图件验收

按[主题、图表与语言规范](visuals.md)查实际 HTML 和独立图件。核对报告及图表语言、图注、标签、表头、状态文字、图例、轴、单位、颜色和图区。桌面及窄屏查 Liquid Glass 目录、代码展开与复制、图片放大和附件链接。所有表格须为 `DT::datatable()`，检查宽表表头与表体对齐，并操作已启用的搜索、排序、分页和表内滚动。独立静态图由正式入口导出矢量 PDF；在任务工作区生成并打开位图预览，查字号、裁剪和对比度。无法审阅交互或预览时标明未验证。
