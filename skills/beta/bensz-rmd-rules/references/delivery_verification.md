# 交付验证（自检报告模板）

在提交 Rmd 给用户前，建议输出一份自检报告，确保“结构 + 解读质量 + 可追溯性”都过线。

## 自检报告模板

```markdown
### 自检报告

| 检查项 | 状态 | 证据/说明 |
|--------|------|----------|
| 混合架构 | ✅/❌ | [.R 负责数据处理（保留完整数据），.Rmd 负责可视化（应用业务阈值）] |
| 数据筛选分离 | ✅/❌ | [.R 未应用阈值筛选，.Rmd 根据业务需求应用阈值] |
| 文件命名一致 | ✅/❌ | [.R、.Rmd、.html 名称一致] |
| 现有资源优先 | ✅/❌ | [使用了哪些 lucky/ccs 函数] |
| 代码简洁可读 | ✅/❌ | [无过度嵌套/管道清晰] |
| 主副分离 | ✅/❌ | [中间函数在 {主脚本名}_functions.R] |
| 不过度保护 | ✅/❌ | [无冗余 if 判断；无 requireNamespace 检查包] |
| 无占位性代码 | ✅/❌ | [无 try-catch 后赋值 NULL/NA/空数据框；失败显式 stop 或有效降级] |
| 跨平台兼容 | ✅/❌ | [使用相对路径 + file.path()] |
| 代码前解释 | ✅/❌ | [每个主要代码块前有“数据特征+方法选择+输出解读”的叙述] |
| 弱背景读者可读性 | ✅/❌ | [已盘点指标；不常用指标有导读表，首次详解定义/原理/理由/判读，后续简写且无失真] |
| 专家级解读 | ✅/❌ | [四层解读过线；Top 信号+效应+不确定性可追溯] |
| 图表/表格解读覆盖 | ✅/❌ | [`check_figure_table_interpretation.py --strict` 通过；无“有输出无解读”漏项] |
| 避免浅层描述 | ✅/❌ | [不是仅“是什么”；有“意味着什么”与可落地后续] |
| AI 图表解读 | ✅/❌ | [基于代码+数据，不是看图说话；用 `r ...` 动态嵌入数值] |
| 图表质量（Nature 级别） | ✅/❌ | [PDF 矢量优先；字体 Arial/Helvetica（缺失则 sans）；色盲友好配色；标签不重叠；图例不遮挡数据] |
| Figure 交付门禁：PDF | ✅/❌ | [每张图都有对应的矢量 PDF（路径清晰、可复现生成）] |
| Figure 交付门禁：JPG 预览 | ✅/❌ | [每张 PDF 都在 run 目录生成了 JPG 预览图（给出路径）] |
| Figure 交付门禁：视觉自检 | ✅/❌ | [AI 已基于 JPG 逐图检查并给出结论（至少：是否裁切/溢出、是否可读、如不可读采取了哪些修复）] |
| 解读-代码一致性 | ✅/❌ | [关键数值/Top 排名/阈值/不确定性来源可追溯] |
| 讨论与分析 | ✅/❌ | [末尾有讨论章节：主要发现+局限+后续建议] |
| YAML 规范 | ✅/❌ | [YAML 头来自 config.yaml:rmd_template.yaml_header] |
```

注意：如有任何项为 ❌，需说明原因或请求用户确认后继续。
```

## 解读-代码一致性自检（交付门槛）

在提交前，关键结论必须可追溯到变量/代码逻辑：

| 问题 | 自检方式（示例） |
|------|------------------|
| 解读中的关键数值是否都能追溯到变量？ | 每个关键数值使用 `` `r variable` `` 或注明来源（变量名/计算式） |
| 解读中的判断是否基于代码逻辑？ | 指出支持该判断的计算来源（例如“从 `common_tbl$n_sig` 提取”） |
| Top 信号是否在数据中可验证？ | 说明排序依据（例如“按 q 值升序取 Top 25”） |
| 不确定性是否来自输出？ | 引用 CI/SE/bootstrap/CV 等输出，而不是主观“可能/提示” |
| 领域见解是否绑定本次变量？ | 明确指出“本次结果中的 X 变量/分层/阈值”，避免泛泛而谈 |

真实填写示例参考：`bensz-rmd-rules/tests/B轮-v202601180903/TEST_REPORT.md`。
