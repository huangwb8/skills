# 四层解读框架（证据锚定 / 反套话 / 可落地）

**来源**：bensz-rmd-rules 核心解读原则

**用途**：提供从数据描述到深刻见解的完整因果链解读标准

---

## 框架概述

对重要输出（图表、统计量、表格）必须提供**多维度、递进式解读**，避免仅有"描述"而无"见解"。

本框架的目标只有一个：让解读**基于当前结果的可验证证据**输出真正有启发性的专家洞见，而不是“看起来很专业”的套话模板。

默认读者相关背景较弱。遇到不常用或任务自定义指标时，先按 `references/metric_explanation_protocol.md` 提供指标导读，并在正文首次出现时解释定义、原理、选用理由与判读方法；从第二次起收敛为证据导向的简洁解读。深入浅出不能改变指标的正式含义或统计边界。

### 四层结构

| 层次 | 核心问题 | 输出要求 |
|------|----------|----------|
| **第一层：数据描述** | 是什么？ | 清晰陈述输出的基本结构和内容，说明关键统计量的数值和显著性 |
| **第二层：统计见解** | 统计上意味着什么？ | 解释效应大小和方向的实际意义，对比不同条件/分组间的差异模式 |
| **第三层：领域见解** | 领域上意味着什么？ | 将统计结果与本领域机制/实践关联，解释发现的潜在价值（不要求“猜文献”，但必须给可验证路径） |
| **第四层：局限与后续** | 下一步该怎么办？ | 指出当前发现的局限性和不确定因素，提出验证或进一步分析的具体建议 |

## 连贯叙述式解读框架

四层框架是**内容门槛**，不是“必须按四段/四条写”的形式模板。常规交付时，推荐把四层内涵自然融入 1–2 段连贯叙述（读起来像专家在讲因果故事，而不是在填检查清单）。

### 适用模式

- **连贯叙述式（默认推荐）**：常规结果、面向人类读者交付；关键结果写得更细，辅助结果简洁说明。
- **分项式（必要时）**：输出复杂（多图/多组/多指标）、需要逐项对齐审查或确保不漏项时使用。

### 段落骨架（隐含四层，外化叙述）

```markdown
[开篇锚定] 本次 [分析类型] 在 [数据规模/条件/阈值] 下评估了 [核心目标]。
[证据锚定] 结果显示 [核心发现]；其中 [Top 1-3 信号] 呈现 [方向 + 效应 + 不确定性] 的模式（用 `r ...` 给出可追溯数值）。
[领域映射] 这在本领域意味着 [为什么重要 + 怎么用/怎么验证]（绑定本次变量/分层/阈值）。
[局限与后续] 需要注意 [局限/不确定性来源]；后续可通过 [验证方案] 在 [输入/数据] 上检验，判据为 [支持/不支持的条件]。
```

### 写完后自检

- ✓ 证据锚定：N/阈值/Top 信号可追溯
- ✓ 统计见解：方向/效应大小/不确定性来自输出
- ✓ 领域映射：为什么重要 + 怎么用/怎么验证（绑定本次变量）
- ✓ 可落地后续：至少 2 条，且每条包含 方法 + 输入 + 判据

### 核心结论（证据链收敛，建议固定产出）

对每个分析单元（如 cohort/亚组/模型）建议固定给出 1 个“核心结论”小节，用于把宏观 → 细节 → 稳健性收敛成可复述结论：

- **Top 1–3** 信号清单（对象 + 数值证据 + 排名/对比）
- **证据强度等级**（强/中/弱）与不确定性来源（CI/SE/Bootstrap/CV 等）
- **可执行后续**：方法 + 输入 + 判据（支持/不支持怎么判）

阈值与判据必须来自 YAML `params`，避免正文硬编码。

## Fail Fast Gate

- [ ] **证据锚定**：每个关键判断都能指向结果中的具体证据（数值/排序/对比/方向/CI/阈值）。
- [ ] **量化优先**：优先用 `` `r ...` `` 内联代码动态嵌入关键数值；不使用“较高/较低/明显/不强”等形容词替代证据。
- [ ] **Top 信号**：明确指出 1–3 个“本次结果的最强信号”，并显式给出**名单**（对象明确，可追溯到指标/排名/数值）。
- [ ] **当前数据观察**：至少 3 句直接陈述本次结果的"具体观察"（对象 + 对比/排序/方向 + 数值证据）。禁止用"图/表是什么、用于做什么"的教学口吻替代结果本身。每句必须包含数值证据（优先 `` `r ...` `` 动态嵌入，或明确可追溯的字面数字）。
- [ ] **不确定性**：至少出现 1 类不确定性/稳定性证据（CI/SE/Bootstrap/CV/敏感性分析等）。
- [ ] **领域映射**：领域层必须回答“为什么重要 + 怎么用/怎么验证”，且对象落到本次结果变量/分层。
- [ ] **可落地后续**：至少 2 条后续验证动作，且每条包含：方法 + 输入 + 判据（支持/不支持怎么判定）。
- [ ] **反套话**：不出现黑名单套话；若表达不确定性，必须同时给对象 + 动作 + 判据。
- [ ] **证据链收敛**（推荐默认）：若存在多个 cohort/亚组/子队列，每个 cohort 至少有 1 段“核心结论（证据链收敛）”，读者只看该段即可复述 Top 1–3、证据强度与下一步验证。

## 硬性最小内容

### 第一层：数据描述（必须出现）

- N（样本/事件/变量/入围数/分组数等）
- 阈值（如 p/q 截断、样本量阈值、过滤规则）
- 输出结构（行列/分组/度量含义）
- 通过/未通过计数（如显著性计数、入围数、缺失比例）

### 第二层：统计见解（必须出现）

- 1–3 个 Top 信号（对象明确：变量/亚组/模型项）
- 方向（正/负；高/低；风险↑/↓；趋势↑/↓）
- 效应大小（beta/OR/HR/差值/增益等）
- 不确定性（CI/SE/稳定性证据/敏感性结果）

### 第三层：领域见解（必须出现）

- 至少 1 条“机制/路径/实践动作”映射，且绑定本次结果对象
- 明确“为什么重要”（与领域目标/决策/机制相关）
- 明确“怎么用/怎么验证”（不许停留在宣言式空话）

### 第四层：局限与后续（必须出现）

- 至少 2 条可落地的验证动作，并绑定本次结果
- 每条动作都包含：方法 + 输入 + 判据

## AI 解读图表的独特优势

**核心原则**：AI 解读 Rmd 生成的图表时，**无需查看渲染后的图像**，应直接分析**生成图表的代码 + 原始数据**。

### 原理

| 解读方式 | 优势 | 局限 |
|---------|------|------|
| **人类看图** | 直观、易理解异常模式 | 无法精确量化，易受视觉偏差影响 |
| **AI 读代码+数据** | 精确量化、无视觉偏差、可复现 | 需代码结构清晰、数据可访问 |

### 最佳实践：动态数值嵌入

解读中的关键数值应使用 Rmd 的**内联 R 代码**动态生成：

```markdown
❌ 硬编码数值（错误）：
该热图缺失比例较高：约 35.2% 的格子为 NA。

✅ 动态嵌入数值（正确）：
该热图缺失比例较高：`r sprintf("%.1f%%", 100 * modules_prop_na)` 的格子为 NA
这意味着在多数癌种里，当前阈值下模块内没有任何显著通路成员。
```

**好处**：
- **精确性**：数值直接来自变量，无复制误差
- **可维护性**：数据更新时解读自动同步
- **可追溯性**：读者知道数值来源（`modules_prop_na`）
- **可验证性**：代码逻辑透明，可独立验证

## 结果锚点句式库（Result-Anchored Patterns）

将抽象判断写成可验证句子；优先使用“对象 + 指标 + 对比 + 方向 + 不确定性”结构。

1. **Top 信号（排序/最强）**
   - 在本次结果中，`X` 是最强信号之一（`metric = ...`，排名 `.../N`），方向为 `...`；与 `Y` 相比差异为 `...`（`CI/SE/稳定性 = ...`）。

2. **阈值解释（把数字翻译成决策含义）**
   - 若以阈值 `T`（来自 `params$...`）解释，该效应对应 `...` 的风险/概率/差异变化，因此在实践上意味着 `...`（适用边界为 `...`）。

3. **不确定性与验证（把“可能”变成可执行验证）**
   - 该结论的不确定性主要来自 `...`（事件数/共线性/非线性/外推性），我们用 `...` 验证：输入为 `...`，判据是 `...`（支持/不支持如何判定）。

## 反套话黑名单 → 替代写法（必须替换）

黑名单不是“禁用表达不确定性”，而是禁用**不带对象与操作的空泛句式**。

| 黑名单套话（示例） | 缺失点 | 必须替换为 |
|---|---|---|
| “提示/可能与…相关” | 无对象/无证据 | 指明对象 + 给出指标/数值 + 对比 + 不确定性 |
| “值得进一步研究/建议进一步验证” | 无动作/无判据 | 给出方法 + 输入 + 判据（支持/不支持怎么判） |
| “结果具有临床意义/可解释/可行动” | 宣言式空话 | 落到本次变量/分层 + 说明怎么用（决策/分层/预测）+ 怎么验证 |
| “可能存在混杂/非线性/交互” | 无定位/无验证 | 指明哪个变量/哪个结论受影响 + 用什么方法检验 + 判据 |

## 正向写作指南：如何写出“证据锚定”的专家洞见

黑名单用于快速自检，但更重要的是掌握“正确写法”。目标是把抽象词（可能/提示/较高/值得）改写成**可验证**的句子。

### 不确定性表达：两种正确方式

1. **量化不确定性（优先）**
   - “效应为 X（95% CI: Y–Z），提示 …”
   - “Bootstrap 1000 次中入选频率为 78%，表明 …”
   - “在交叉验证中该指标的中位数为 …（IQR: …），说明 …”

2. **可验证的假设（必要时）**
   - “若 X 成立，我们预期在 [数据/条件] 中观察到 [模式]；可通过 [方法] 验证，判据为 [支持/不支持的条件]。”
   - （避免：只写“可能/提示/值得进一步研究”，却不给可执行验证。）

### Top 信号的标准表述句式（可复用，不强制套用）

- “`变量名` 是本次最强信号之一（`指标` = `值`，排名 `位次/N`），方向为 `正/负/风险↑/↓`，与 `参照` 相比差异为 `值`（`CI/SE/稳定性证据`）。”
- “在 `条件/亚组` 中，`变量` 呈现 `模式`，提示 `机制/路径/实践启示`；但需注意 `局限`，可通过 `验证方案` 在 `输入/数据` 上确认（判据：…）。”

## 示例对比

### ❌ 浅层解读（教学口吻 + 仅有描述）

```markdown
该表包含 700 行（每行对应"一个癌种 × 一个基因"），覆盖 28 个癌种与 25 个 top genes。
effect > 0 表示该 mutation 事件在 normCCS 更高的样本中更常见；effect < 0 则相反。
生成条件：默认仅展示样本量 ≥ 60 的癌种。
```

**问题分析**：这段文字是在"教用户怎么看这类表"，而不是"告诉用户当前这张表展示了什么发现"。

### ❌ 半成品解读（骨架版，仍含通用套话）

```markdown
本次分析汇总了 28 个癌种 × 25 个 Top 基因的 mutation 效应。
最强信号集中在 [癌种 A] 和 [基因 B]（按 q 升序排序），提示该突变与 normCCS 相关。
该结论可能受共突变混杂影响，后续建议进一步验证。
```

**问题分析**：虽然格式看起来专业，但 `[癌种 A]`、`[基因 B]` 是占位符而非当前数据的具体对象；"建议进一步验证"是无方法/无输入/无判据的空话。

### ✅ 专家级解读（血肉版，绑定当前数据）

```markdown
本次分析在样本量阈值 `r params$min_n` 的条件下，汇总了 `r n_cancer` 个癌种 × `r n_top` 个 Top 基因的 mutation 效应（共 `r nrow(tbl)` 行）。

**最强信号集中在 `r top_gene_1`（effect = `r top_effect_1`，q = `r top_q_1`）、`r top_gene_2`（effect = `r top_effect_2`，q = `r top_q_2`）、`r top_gene_3`（effect = `r top_effect_3`，q = `r top_q_3`）**。三者均呈现**正向关联**（effect > 0），提示这些基因的突变更倾向出现在 normCCS 较高的样本中。

在癌种层面，`r top_cancer_1` 的信号最集中（`r n_sig_in_cancer_1` / `r n_top` 个基因通过 q ≤ 0.05 阈值），中位 effect 为 `r median_effect_cancer_1`（IQR: `r iqr_effect_cancer_1`）；相比之下，`r top_cancer_2` 仅有 `r n_sig_in_cancer_2` 个基因通过阈值，中位 effect 为 `r median_effect_cancer_2`，**提示癌种异质性可能影响信号泛化**。

**领域意义**：若将 `r top_gene_1` 和 `r top_gene_2` 作为候选分层标志物，其突变携带率分别为 `r sprintf("%.1f%%", 100*freq_gene_1)` 和 `r sprintf("%.1f%%", 100*freq_gene_2)`（当前队列），足以支持后续分层分析。

**不确定性与验证**：该结论的主要不确定性来自共突变混杂（当前 `r top_gene_1` 与 `r top_gene_2` 的共突变率为 `r sprintf("%.1f%%", 100*co_mutation_rate)`）。后续可在多因素模型中加入共突变项；判据：调整后 `r top_gene_1` 的 effect 方向一致且 q ≤ 0.1。同时建议在 TCGA 独立队列复现（判据：方向一致率 ≥ 70%）。
```

**为何是血肉版**：每句话都绑定 `` `r ...` `` 动态数值；指出"本次最强信号"具体是哪几个对象；癌种对比有具体数值；"验证"有方法 + 输入 + 判据。

### ✅ 专家级解读：连贯叙述式（简洁版）

```markdown
本次 `r n_samples` 个样本的分析中，扩增负荷与 normCCS 呈现**强正相关**（Spearman rho = `r sprintf("%.3f", macro_rho)`，p < 0.001）。**最强信号集中在 `r top_cancer_1`**，其中位负荷为 `r median_burden_high`（IQR: `r iqr_burden_high`），显著高于 `r top_cancer_2` 的 `r median_burden_low`（IQR: `r iqr_burden_low`）。在排序前 `r k` 个样本中，有 `r m` 个来自高 normCCS 组（超预期的 `r sprintf("%.1f%%", 100*m/k)`），**提示扩增负荷可能主导了该亚组的总体差异**。

该结论的不确定性主要来自：当前 `r top_cancer_1` 样本量为 `r n_cancer_1`，且 `r confounding_var` 可能作为混杂因素。后续可通过分层分析检验稳定性（判据：分层后 rho 方向一致且 p < 0.05），或在 `r external_cohort` 队列复现。
```

## 数据溯源要求

解读中提及的数值必须明确其来源：

| 数值类型 | 溯源方式 | 示例 |
|---------|---------|------|
| **统计量** | 引用变量名或函数调用 | `p = \`r summary(fit)$pval\`` |
| **样本量** | 引用数据框维度或计数 | `N = \`r nrow(survival_data)\`` |
| **比例/百分比** | 引用计算逻辑 | `缺失比例 \`r sprintf("%.1f%%", 100 * prop_na)\`` |
| **阈值** | 引用参数变量 | `q ≤ \`r q_cutoff\`` |

## 解读-代码一致性验证

生成解读前，AI 应自检：

```
解读中的每个数值是否都能在代码/数据中找到对应来源？
- "p < 0.001" → 是否来自 `summary(fit)$pval` 或类似计算？
- "样本量 500" → 是否来自 `nrow(data)` 或 `length(unique(...))`？
- "缺失 35.2%" → 是否来自 `sum(is.na(x)) / length(x)`？
```
