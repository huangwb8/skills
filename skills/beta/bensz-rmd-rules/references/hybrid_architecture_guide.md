# 主业与副业分离（.R + .Rmd 混合架构）

## 四元架构（.R + .Rmd 混合模式）

每次生成 Rmd 分析，建议遵循以下结构：

```
项目目录/
├── {主脚本名}.R            # 数据脚本：数据处理、计算、保存结果
├── {主脚本名}.Rmd          # 主脚本：可视化、分析、解读
├── {主脚本名}_functions.R  # 副脚本：中间函数
├── 00.Environment.R        # 环境脚本：R 包加载、全局配置
└── tmp/{主脚本名}/         # 临时文件夹：局部分析
```

核心设计理念：

| 组件 | 职责 | 数据状态 | 优势 |
|------|------|----------|------|
| **.R 数据脚本** | 数据处理、重型计算、特征工程 | **未经阈值筛选的完整数据** | 计算一次，保存结果，用户可审查原始状态 |
| **.Rmd 主脚本** | 基于 .R 结果的可视化与分析 | **根据业务需求应用阈值筛选** | 灵活调整筛选策略和可视化，无需重复计算 |
| **_functions.R** | 当前分析专用的中间函数 | - | 逻辑内聚，易于维护 |
| **00.Environment.R** | 全局环境配置 | - | 跨脚本共享，统一管理 |

数据筛选职责分离原则：

```
.R 脚本                         .Rmd 分析
┌─────────────┐               ┌─────────────┐
│ 原始数据处理 │               │ 业务需求筛选 │
│             │               │             │
│ 保留全部数据 │ ──传递完整数据──► │ 应用阈值筛选 │
│             │               │             │
│ 方便用户审查 │               │ 确保分析价值 │
└─────────────┘               └─────────────┘
```

- **.R 脚本**：生成未经阈值筛选的完整数据集，保存所有样本和特征，方便用户审查数据最原始的状态
- **.Rmd 分析**：根据具体业务需求和统计要求，对 .R 提供的完整数据应用阈值筛选（如表达量阈值、p 值/q 值阈值、样本量要求等），从而保证分析具有科学价值和可解释性

实践示例与 YAML params 的典型写法见 `references/hybrid_architecture_examples.md`。

文件命名约定：

- `.R`、`.Rmd`、`.html` 文件除后缀外，名称必须完全一致
- 函数脚本命名：`{主脚本名}_functions.R`（如 `cf01_functions.R`）

## 从本 skill 的模板快速起手

当用户需要创建新的 Rmd 分析时，可参考本 skill 的模板：

- 数据脚本模板：`templates/R_data_template.R` -> `{主脚本名}.R`
- 主脚本模板：`templates/Rmd_template.Rmd` -> `{主脚本名}.Rmd`
- 函数脚本模板：`templates/functions_template.R` -> `{主脚本名}_functions.R`
- 环境脚本模板：`templates/00.Environment.R` -> `00.Environment.R`

增量操作：

- 若 `{主脚本名}_functions.R` 已存在：仅增量添加所需函数，严禁覆盖
- 若 `00.Environment.R` 已存在：仅增量添加所需内容，严禁覆盖

## 数据脚本规范（{主脚本名}.R）

数据脚本负责数据处理和重型计算，建议遵循：

1. 计算与保存分离：所有耗时计算完成后，保存为 `.rds`
2. 数据完整性：保存尽量全面的数据，为后续 .Rmd 分析提供充分素材
3. 不应用业务阈值筛选：保留“可审查的原始状态”
4. 可独立运行：直接 `source()` 即可完成数据处理与保存
5. 清晰输出：每个主要步骤打印进度信息

可选优化：postprocess-only 模式

- 当首次计算很慢、后续主要是“调阈值/调图表/补充解释”时，可让 `.R` 进入“只读已有输出并补齐”的快速模式
- 实现细节按项目自定，避免在主脚本里堆复杂框架

数据保存约定（最小口径）：

- 输出目录：`tmp/{主脚本名}/`
- 常见文件：`processed_data.rds`（处理后数据）、`computation_results.rds`（计算结果）（如需可加 `raw_data.rds` 备份）

## 主脚本规范（{主脚本名}.Rmd）

主脚本基于 .R 的结果进行可视化与分析，建议遵循：

1. 加载 `.R` 结果：从 `tmp/{主脚本名}/` 读取产物（通常用 `readRDS()`）
2. 在 `.Rmd` 应用业务阈值：把阈值/展示策略放在 YAML `params` 里，便于迭代
3. 可视化与解读优先：避免重复重型计算
4. 不动用户代码：对已有文件只做增量修改

必须包含与 `templates/Rmd_template.Rmd` 等价的 load-data chunk（source `00.Environment.R` -> 校验 `tmp/{主脚本名}/` -> `readRDS()`）。

## 函数脚本规范（{主脚本名}_functions.R）

在 `{主脚本名}_functions.R` 中添加当前分析专用的中间函数：

- 建议以 `templates/functions_template.R` 为骨架
- 必须增量添加，严禁覆盖原有内容
- 函数名以 `.` 开头 + 主脚本名缩写 + 功能描述
- 按功能分组（数据/可视化/统计），保持内聚性

## 临时文件夹用途（tmp/{主脚本名}/）

`tmp/{主脚本名}/` 的使用场景：

- 中间结果缓存
- 调试用测试代码
- 局部分析产物

生命周期管理：

- 创建时机：需要时用 `dir.create(recursive = TRUE)`
- 清理策略：由用户手动清理，AI 不主动删除用户数据
- 冲突处理：目录已存在则复用；文件冲突时加时间戳后缀（如 `analysis_YYYYMMDD.R`）
