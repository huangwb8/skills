# 数据、代码与结果的可重建契约

## 完成标准

默认派生数据、`_targets/`、图表和报告都可能丢失。只保留受保护输入、源码、分析/报告参数及环境声明，从文档化正式入口能重新生成约定交付，才可称为可重建。中断续算与无缓存重建分别验收：前者证明节省重算，后者证明结果不依赖旧现场。

本契约适用于 simple 和 complex。新建或实质修改流程须覆盖受影响链路；已有项目沿原入口验证，不因本契约自动补建 renv、targets 或迁移。授权范围内无法闭合的数据来源、路径或执行步骤，应明确标为风险/阻塞。小改不要求重跑无关全量分析，但不能沿用已失效的测试证据。

## 先区分输入和可再生产物

- 原始数据只读。人工标签、手工修订、无法再次取得的 API 响应、唯一来源模型或上游结果，均是受保护输入，即使它们看起来像“中间文件”。记录来源、版本、schema、适当的内容指纹和取得/恢复方式。
- 清洗、过滤、特征构建、模型拟合、导出和绘图均写入正式源码。人工改结果表或图后，须把修改落实到生成代码/参数；不能只保存修改后的文件。
- 外部数据库/API/注释资源固定版本或保存获授权的必要快照。无法固定或留存时明确复现边界和重建前提，不承诺未来实时请求结果相同。
- 输入清单/内容指纹用于身份和审计；complex 的缓存失效仍交给 targets，不新增 identity runner、SUCCESS 或完成标记。

## 路径与依赖必须闭合

项目根由入口明确定位，或说明“从项目根启动”并验证根标识；不得把任意 `getwd()` 静默当根。路径从单一项目配置解析；不得猜最新文件、扫描磁盘寻找替代输入、硬编码个人盘符或回退到旧结果。外部授权输入如不能复制进项目，按已有授权路径配置并披露迁移前提；新模板默认限定项目内输入。公开摘要只记相对路径或逻辑数据 ID，不记录私有绝对路径。

每个关键交付至少对应：输入身份 → 代码/函数/target → 分析参数与随机策略 → 输出路径 → 正式重建命令 → 验收判据。simple 可用短表；complex 使用 DAG 与 `analysis-plan.yaml`。正式代码不得依赖 `.RData`、交互会话对象、临时目录中的唯一代码或未记录的手工顺序。

complex 必须做到：

- 外部文件内容用 `format = "file"` 或等价成熟格式跟踪。仅把路径字符串作为普通 target，不能证明该路径内容变化会使下游失效。
- 环境变量/YAML/模型配置先解析为显式依赖。不要只在 target 函数内部读 `Sys.getenv()`、时钟或隐藏全局选项；targets 不会自动追踪所有外部状态。YAML 文件本身须纳入文件依赖，解析后供下游消费。
- 文件型产品/报告进入 file target，或提供每次正式运行都会执行的明确导出/渲染步骤。删除交付文件后能补齐，不能仅因计算 target 有效就跳过导出。`file.exists()` 本身不是有效性证明。
- 分析参数（包括影响估计值的阈值）进入计算依赖；Top N、配色、显示阈值等纯展示参数留在报告层。随机策略显式声明；固定种子不保证跨 R/算法/硬件字节一致。
- Rmd 消费计算产品，不从 raw 绕过 DAG 重做昂贵计算。单独渲染前须确认输入/计算仍有效，不能把陈旧 store 的报告当成更新后的分析。

## 环境与正式入口

新项目交付 `renv.lock`、激活入口、R 版本和影响结果的系统依赖/外部资源版本。环境恢复是显式准备步骤，不在每次计算中静默安装或 snapshot。按需要记录 Pandoc、系统库、locale/timezone、并行和数值库；不要假设 renv 锁住了这些。

交付可复制的命令及其 cwd、输入位置和参数来源：

1. 环境恢复：例如项目根中 `Rscript --vanilla -e 'source("renv/activate.R"); renv::restore(prompt = FALSE)'`。
2. 全部结果重建：simple 的正式 R/Rmd 入口；complex 的 `tar_make()` 加完整交付导出/渲染入口。报告位于 DAG 外时必须列出渲染命令和参数，不能只交 `tar_make()`。
3. 仅重出报告：从确认仍有效的完整结果重渲染，不重复无关重型计算。

模板以项目根为 cwd。`00.Environment.R` 验证这一前提。`callr_function = NULL` 只控制是否另起调用进程，不强制重算；主动失效使用 targets 官方接口，不能自动删除正式 store。

## 隔离轻量验收

先建立唯一 `tmp/tests/<run-id>/`，采用已授权代表性子集或合成数据。只在新建隔离副本内执行结果删除和输入变更；禁止对用户正式 `raw/`、产品、报告、store 或唯一来源材料进行“破坏式验证”。迁移副本使用可追溯的代码/配置快照与必要渲染资产，不复制凭据、真实全量数据、旧结果或无关缓存；敏感子集按既有清理规则删除。

用正式入口、相同业务函数、相同科学参数在新 R 子进程中执行；不能用测试专用计算路径绕过正式逻辑。模板 smoke 提供干净进程和冷重建/交付恢复起点，仍须按真实项目补充科学断言、输入变化、迁移及中断用例。

| 场景 | 实际操作与最低断言 |
| --- | --- |
| `cold_rebuild` | 输入/代码/参数/环境不变，隔离副本无派生结果、store 和报告，从干净进程重建；每项关键交付存在、非空且可读取，关键数值与结构符合预定判据。 |
| `missing_delivery` | 保留有效计算缓存，移除隔离副本中一个产品或报告，再运行正式交付入口；缺失文件恢复，complex 的无关昂贵 target 不重算。simple 的低成本全量重跑可接受。 |
| `input_content_change` | 原始文件不动，只修改测试输入副本的内容且路径不变；再次正式运行后指定下游值按预期变化。complex 确认受影响节点失效、无关分支复用，不只看退出码或时间戳。 |
| `relocated_project` | 把同份代码/参数/轻量输入放到另一个项目路径，不带旧结果/store；按文档从新根运行，关键数值与结构在预定容差内一致。相对文件引用正确；不要求支持任意 cwd，但错误 cwd 必须明确失败。 |

complex 另按缓存契约验证真实中断后有效前序复用。上述验收可复用同一轻量输入与结果断言，避免重复全量计算。预先确定数值容差、列/键/顺序语义和必须交付清单；HTML/PDF 通常比较可读性和科学内容，不要求日期、字体元数据或文件字节相同。仅复制旧结果不能算重建。

每个场景分别记录 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`，确无适用对象可记 `NA` 并说明；附最新代码/配置/lockfile 身份、非敏感输入身份、参数/种子、命令/cwd、退出状态、断言与结果来源。轻量场景通过不代表全量通过；受影响必需场景失败、阻塞或未运行时，不能宣称该链路已完整验证可重建。
