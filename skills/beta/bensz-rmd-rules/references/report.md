# 推断与报告

## 写之前先决定什么可以回答

每个关键问题用一行写清「判断 → 比较和分析单位 → 可用证据 → 结论边界」。需要推断时先确定 estimand、效应尺度、对照、分析人群、缺失与排除规则、配对/聚类/时间结构和不确定性方法。跨队列或拟合与验证分离时核实独立性、泄漏和患者层分母。观察性、预测性和因果判断各用其证据；探索结果明确标识。

如果用户只给题目或数据，主动把宽泛主题变成有实际意义、现有设计可检验的问题。多问题时，让后续比较承接前一项的未决之处。遇到反直觉结果，先核查口径和数据，再尽可能用对照或敏感性分析区分解释；没有相应证据时，把机制解释留作假说。

关键结果尽量保留完整、未经显著性筛选的估计表：有效样本和事件数、估计和单位、适当的区间/置信水平、方法及状态。只有存在合适检验和假设时报告 p 值，多重检验说明比较族及调整；不可估计、未运行或不适用时给理由。比如配对 AUROC 差异应在共同可评分单位上比较，并汇报各法覆盖，bootstrap 的抽样单位与区间条件须和设计一致。不要从覆盖差异、单独区间或一个 p 值推出互换性。

## 组织成可以读完的证据链

开篇给与用途相称的判断。随后按科学问题展开：读者为什么关心、这个比较能排除哪种解释、什么结果会改变判断。用真实代码交代配对、分组、分母或模型选择；用图呈现方向、例外、异质性或不确定性；用短表列出需要精确查读的数字；用文字解释证据怎样接到结论、它还允许哪些解释。按问题多少决定篇幅，避免四种形式重复同一条信息。

例如判定两种读数能否互换：用真实代码或简短摘录显示如何构造同一批配对样本；用图画出差异及区间，标明适用的阈值；正文为会改选择的少数分层给精确分母。若缺跨平台证据，可结论为「在当前验证条件下保留现方案」，并解释在哪些条件下要改路。

## 把完整研究写成论文式报告

每份新分析都写成完整报告，由 targets 与 renv 支撑。先在授权范围内完成数据核对、主要分析、关键诊断并解读结果，再据此写讨论和摘要。篇幅应足以走完论证：复杂或会影响决策的分析多写方法、诊断与结果解读，保留正文中的关键证据，把大表和长实现放在附录。没有最低字数或图表配额。已有报告的局部修改只触及授权范围。

| 章节 | 读者应能找到的内容 |
| --- | --- |
| 摘要 | 问题、设计与样本、主要比较及其效应与不确定性、结论边界。正文证据齐备后再定摘要，用内联 R 引用同一组数字。 |
| 引言 | 研究背景、实际决策或知识缺口、为什么现有问题值得分析、主要和补充问题。外部事实使用可核实的来源。 |
| 数据与方法 | 输入与分析单位、纳入与排除、实际分母、变量与时间口径、比较设计、关键方法与参数的选择理由。展示会改变结果的代码。 |
| 结果 | 按科学问题组织，在解释方法后给出实际代码、结果与解读。交代估计量级、方向、区间、例外和未估计的比较；正文说明关键图表的具体读法。 |
| 质量控制与数字核对 | 报告实际检查、观察到的数值或状态、异常的影响和处理。主要结果应能从摘要或正文回溯到正式结果字段、生成代码、图表与分母。 |
| 讨论 | 综合主要、补充和相反证据；说明可能的替代解释、推断和外推边界、会改变判断的条件，提出有输入、方法和判据的下一步。 |
| 可复现性 | 数据或版本来源、决定结果的参数与代码入口、环境、正式重建与报告专用入口；说明产物如何取得及访问限制。 |

给每个主要结果完整展开论证：先说明为何需要这一步、数据有何约束、哪个对照或方法可以回答；展示实际代码及必要输出；再用内联数字解释观察到了什么、量级对问题意味着什么、还有什么可能推翻解释。让后续分析承接前一节的疑问。例如，平均值可能被少数样本拉动，就先看个体分布，再判断是否值得做单点影响检查；拟合与评估可能共享信息，就核对拆分独立性和预处理边界。方法与诊断应匹配数据和目标；有关稳健性、敏感性或验证的结果要说明改变了哪一处口径、保留了哪些条件、比较指向什么。缺少输入或无法估计时给出理由和对结论的影响。

### 科学质控要给证据

按设计选择要查的风险，例如样本纳入与分母、ID 与单位、缺失和排除、异常值、训练验证隔离、统计假设或性能的适用范围，以及不同产物之间的数字一致性。每项说明检查对象、判据、实际结果和异常处置；区分通过、发现问题、未执行、不可判断或不适用。在正文交代会改变解读的异常及其影响；长报告可用 DT 表提供关键数字的来源和位置。只写“已通过质控”或列出将来拟做的检查不能替代实际结果。科学质控复核输入和推断；[测试与交付](delivery.md)还要检查实际重建及 HTML。

## 用例子建立直觉，再给出数学定义

围绕关键且不容易理解的概念、方法或发现，用一条连续的解释服务不同背景的读者：

1. **给一个能手算的小例子。** 例如换路线前后比较通勤时间：甲从 25 到 30 分钟，乙始终是 40 分钟，两人的变化是 +5 和 0，平均 +2.5 分钟。这个假设例子说明每个人先与自己的基线配对；它不代表实际数据，也不能证明路线造成了变化。
2. **把例子与实际口径对齐。** 若报告估计完整配对的平均变化，写作 $d_i = y_{i,1} - y_{i,0}$、$\bar d = n^{-1}\sum_{i=1}^{n}d_i$。说明 $y_{i,0}$ 和 $y_{i,1}$ 是同一单位前后两次测量，$n$ 只数有效配对，正值表示上升，单位与原测量一致。用加权估计、变换尺度或不同区间算法时，公式要如实反映代码；区分指标定义、估计式和推断所需的假设。
3. **用真实结果把解释收回来。** 指向实际图表和效应尺度，解释观察到了什么，有哪些反例或不确定性。比如一个正的平均变化仍可包含不变或下降的个体；失访单位不会进入配对平均，差异区间跨零也不能作为等效的证据。

不要为熟悉的指标逐个写类比或公式。对影响结论的概念，正文应容纳直觉和核心公式；较长推导放附录，主线仍需说明它如何影响解释。类比只迁移对应的关系；公式要能沿着符号、分母和单位追到真实计算。Rmd 用 `$...$` 或 `$$...$$`，HTML 可用原生 MathML（`mathjax: null` 与 `pandoc_args: ["--mathml"]`）在现代浏览器离线展示。

## 代码怎么展示，数字怎么引用

每个主要分析块之前先用一小段话说清：这一步用到哪些数据，数据有什么会影响比较的特点，为什么选这个方法或参数，以及接下来的输出能回答什么。把主要代码放在对应结果附近。图表之后用自己的话解释观察到什么、证据支持到哪一步；代码负责填数字、组名和可估计状态等可核对的事实。

| 代码角色 | 展示 | 执行 |
| --- | --- | --- |
| 分组、配对、精确分母和指标定义 | 默认展开正式实现的关键片段，可展开较长部分 | targets 正式计算，Rmd 读取经核验的结果 |
| 拟合、重采样、统计诊断与稳健性分析 | 在结果旁默认展开决定口径的短片段，长实现可折叠并链接完整源码 | targets 正式计算，Rmd 读取经核验的结果 |
| 图表和数字展示 | 图表生成代码默认展开，常规样式可隐藏 | Rmd 可筛选、排序、格式化、绘图、制表，并核对产物一致性 |
| 加载包、配置路径和重复排版 | 通常隐藏 | 只做渲染所需的工作 |

R Markdown HTML 默认 `code_folding: show`，单个长块可用 `class.source = "fold-hide"`。`echo = FALSE` 仅隐藏源码；`eval = FALSE` 展示摘录但不执行。摘录从本次正式实现提取，并附可访问的源码链接。已有报告保留项目明确的可见性要求或用户指定的风格。

正文、摘要和图注里的关键数字默认用内联 R 引用命名的结果对象或从它派生的展示值，包括分母、效应、不确定性和采用的分析阈值。内联表达式尽量只取值或格式化；复杂筛选、统计量和分支先在代码块或计算端定义。相同的数字出现在正文、表格和图中时，共用结果及适用的展示值。固定文献数字和假设例子标明来源或性质；既有正式结果只能以固定快照复用时，尽可能读入该快照后内联引用，确实只能手引时写明具体来源和位置。正文按需舍入，正式结果保留原精度。

例如，报告前文解释为何以完整配对为分母，再运行或展示正式实现；展示值建立后，正文可以写成：

```markdown
完整配对为 `r pair_count`，平均变化为 `r mean_value` 个测量单位，
`r confidence_label`：`r interval_value`。
```

## 用 DT 展示报告表格

图形编码、图表语言、独立图件和报告主题的默认要求见[主题与图表规范](visuals.md)。

只要在 Rmd 报告里展示表格，就必须用 `DT::datatable()`，包括正文里的短汇总表、附录和长宽明细。短表可只显示表格（如 `options = list(dom = "t", paging = FALSE, ordering = FALSE)`）；明细按需启用搜索、排序、分页或 `scrollX`。将 `DT` 纳入项目依赖。直接在代码块输出 widget，赋值后显式输出；循环或折叠区须在浏览器复核。填写单位、精度、分母、缺失和特殊编码。

只展示部分记录时，说明选择标准与范围；分页不减少客户端下载的数据。数据太大或不允许嵌入时，在报告里用文字或获准的 DT 汇总，完整明细按授权单独交付。

骨架默认用 DT 渲染正文汇总表。加 `--detail`（也接受旧参数 `--dt`）会追加[逐单位配对明细](../templates/detail/appendix.Rmd)，从正文已读取的 `paired_changes` 结果展示差值及是否纳入估计。换成真实数据前，先确认是否允许在 HTML 中嵌入逐条记录和单位编号。
