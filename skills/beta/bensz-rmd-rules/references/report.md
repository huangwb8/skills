# 推断与报告

## 写之前先决定什么可以回答

每个关键问题用一行写清「判断 → 比较和分析单位 → 可用证据 → 结论边界」。需要推断时先确定 estimand、效应尺度、对照、分析人群、缺失与排除规则、配对/聚类/时间结构和不确定性方法。跨队列或拟合与验证分离时核实独立性、泄漏和患者层分母。观察性、预测性和因果判断各用其证据；探索结果明确标识。

如果用户只给题目或数据，主动把宽泛主题变成有实际意义、现有设计可检验的问题。多问题时，让后续比较承接前一项的未决之处。遇到反直觉结果，先核查口径和数据，再尽可能用对照或敏感性分析区分解释；没有相应证据时，把机制解释留作假说。

关键结果尽量保留完整、未经显著性筛选的估计表：有效样本和事件数、估计和单位、适当的区间/置信水平、方法及状态。只有存在合适检验和假设时报告 p 值，多重检验说明比较族及调整；不可估计、未运行或不适用时给理由。比如配对 AUROC 差异应在共同可评分单位上比较，并汇报各法覆盖，bootstrap 的抽样单位与区间条件须和设计一致。不要从覆盖差异、单独区间或一个 p 值推出互换性。

## 组织成可以读完的证据链

开篇给与用途相称的判断。随后按科学问题展开：读者为什么关心、这个比较能排除哪种解释、什么结果会改变判断。用真实代码交代配对、分组、分母或模型选择；用图呈现方向、例外、异质性或不确定性；用短表列出需要精确查读的数字；用文字解释证据怎样接到结论、它还允许哪些解释。按问题多少决定篇幅，避免四种形式重复同一条信息。

例如判定两种读数能否互换：用真实代码或简短摘录显示如何构造同一批配对样本；用图画出差异及区间，标明适用的阈值；正文为会改选择的少数分层给精确分母。若缺跨平台证据，可结论为「在当前验证条件下保留现方案」，并解释在哪些条件下要改路。

## 用例子建立直觉，再给出数学定义

围绕关键且不容易理解的概念、方法或发现，用一条连续的解释服务不同背景的读者：

1. **给一个能手算的小例子。** 例如换路线前后比较通勤时间：甲从 25 到 30 分钟，乙始终是 40 分钟，两人的变化是 +5 和 0，平均 +2.5 分钟。这个假设例子说明每个人先与自己的基线配对；它不代表实际数据，也不能证明路线造成了变化。
2. **把例子与实际口径对齐。** 若报告估计完整配对的平均变化，写作 $d_i = y_{i,1} - y_{i,0}$、$\bar d = n^{-1}\sum_{i=1}^{n}d_i$。说明 $y_{i,0}$ 和 $y_{i,1}$ 是同一单位前后两次测量，$n$ 只数有效配对，正值表示上升，单位与原测量一致。用加权估计、变换尺度或不同区间算法时，公式要如实反映代码；区分指标定义、估计式和推断所需的假设。
3. **用真实结果把解释收回来。** 指向实际图表和效应尺度，解释观察到了什么，有哪些反例或不确定性。比如一个正的平均变化仍可包含不变或下降的个体；失访单位不会进入配对平均，差异区间跨零也不能作为等效的证据。

不要为熟悉的指标逐个写类比或公式。对影响结论的概念，正文应容纳直觉和核心公式；较长推导放附录，主线仍需说明它如何影响解释。类比只迁移对应的关系；公式要能沿着符号、分母和单位追到真实计算。Rmd 用 `$...$` 或 `$$...$$`，HTML 可用原生 MathML（`mathjax: null` 与 `pandoc_args: ["--mathml"]`）在现代浏览器离线展示。

## 分别决定展示和执行

| 代码角色 | 展示 | 执行 |
| --- | --- | --- |
| 分组、配对、精确分母和指标定义 | 优先显示关键行；较长时折叠 | 在正式分析端或轻量 simple 入口执行；complex Rmd 可筛选、排序和绘图 |
| 拟合、重采样和昂贵外部产品 | 需要时展示对应实现的简短摘录或链接 | 正式计算端执行，报告读取已核验的结果 |
| 包、路径和重复排版 | 通常隐藏 | 只做渲染所需的工作 |

`echo = FALSE` 仅隐藏源码；`eval = FALSE` 才让代码摘录不执行。用代码链接或相同的实现片段绑定结果，避免展示与实际口径分叉。关键叙述数字可用内联 R 或明确的结果引用。正文使用足够精度，来源保留原精度。

## 用 DT 展示报告表格

图形编码、图内语言、独立图件和报告主题的默认要求见[主题与图表规范](visuals.md)。

只要在 Rmd 报告里展示表格，就必须用 `DT::datatable()`，包括正文里的短汇总表、附录和长宽明细。短表可只显示表格（如 `options = list(dom = "t", paging = FALSE, ordering = FALSE)`）；明细按需启用搜索、排序、分页或 `scrollX`。将 `DT` 纳入项目依赖。直接在代码块输出 widget，赋值后显式输出；循环或折叠区须在浏览器复核。填写单位、精度、分母、缺失和特殊编码。

只展示部分记录时，说明选择标准与范围；分页不减少客户端下载的数据。数据太大或不允许嵌入时，在报告里用文字或获准的 DT 汇总，完整明细按授权单独交付。

骨架默认用 DT 渲染正文汇总表；加 `--detail`（也接受旧参数 `--dt`）会追加[长宽表片段](../templates/optional/long-table.Rmd)和合成 CSV。按正式入口构建后，在窄屏实际横向滑动，确认是表内滚动，并核对附件链接和显示范围。
